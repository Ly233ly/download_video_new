## 设计原则

这三条是全部取舍的依据，任何设计冲突都按此裁决。

### 1. 功能优先

不为假想场景增加复杂度。每引入一个机制，必须回答：**它解决了用户实际遇到的什么问题？** 答不上来就不做。

### 2. 防自己出错，不防攻击

对手不是攻击者，是**程序自己的 bug**。

| 要做 | 不做 |
| --- | --- |
| 不误删用户文件 | 防同机恶意进程 |
| 崩溃后不断网 | 防伪造 Origin 头 |
| 不损坏数据库 | 防时序攻击 |
| 不静默降级画质 | 防侧信道 |
| 路径穿越 / 命令注入（这是 bug） | 配对认证、令牌轮换 |

保留的校验都是**输入合法性校验**，不是身份与权限体系。

### 3. 一处事实，一处定义

同一个值、同一条规则、同一个配置，只允许有一个权威定义位置。其余地方引用它。

## 架构总览

```text
┌─ 留底下载器.exe ──────────────────────────────────┐
│  UI (WebView2)  ←Wails 绑定/事件→  Go 后端         │
│                                                   │
│  Go 后端：下载引擎 · 本地 API · SQLite · 日志       │
│                                                   │
│  捕获守护：按需启动子进程，持有代理恢复责任          │
└───────┬───────────────────────────┬───────────────┘
        │ 管道 JSON-RPC              │ 回环 HTTP
        │ (stdin/stdout)             │ (Origin 白名单)
        ▼                            ▼
┌────────────────────┐      ┌──────────────────┐
│ liudi-capture.exe  │      │  浏览器扩展       │
│ MITM 代理（按需）   │      │  (纯 JS, MV3)    │
│ 页面 bridge 注入    │      └──────────────────┘
└────────────────────┘
        ▲
        │ 代理拦截 /__liudi/report
        │
   [微信内嵌页面 bridge]

┌────────────────────┐      ┌──────────────────┐
│ IdmEagleHook.exe   │─────▶│ inbox/ 目录       │
│ 只投文件，不碰库    │      │ + 命名事件        │
└────────────────────┘      └──────────────────┘

┌────────────────────┐
│ 留底安装器.exe      │  独立单文件
└────────────────────┘
```

### 通信方式（全部简单）

| 通道 | 方式 | 认证 |
| --- | --- | --- |
| UI ↔ Go | Wails 绑定 + 事件推送 | 同进程，无需认证 |
| 扩展 ↔ Go | 回环 HTTP | **仅 Origin 白名单** |
| Go ↔ 捕获子进程 | **管道 JSON-RPC**（stdin/stdout） | 父子关系即身份 |
| 网页 bridge → 捕获 | 代理拦截 `/__liudi/report` | 无端口、无令牌 |
| hook → Go | inbox 目录文件 + 命名事件 | 本地目录 |

**没有**：端口令牌、配对码、bootstrap 秘密、令牌恢复流程、租约归属判定。

### 关键机制

| 机制 | 做法 |
| --- | --- |
| 崩溃不断网 | 启动**第一件事**检查代理残留并恢复；子进程崩溃由父进程立即恢复 |
| 界面不卡 | 前端**不轮询**，全部状态由事件推送 |
| 不删用户文件 | 只删程序写入「已完成」目录且记录匹配的文件 |
| 画质不降级 | FFprobe 实测校验，失败即报错而非交付低清 |
| 链接拿不到时有退路 | **浏览器下载模式**（扩展弹窗内开关，默认关闭）：用浏览器自身会话取字节，流式中转给桌面端后照常合并校验落盘 |
