## 1. 匹配范围

`douyin.com` 与其全部子域。

**不覆盖**：直播间地址、图文（非视频）内容页、分享短链落地页之外的中间页。

---

## 2. 抓取方法

抖音页面同时存在多个 `<video>` 元素，且地址栏随信息流滚动而变（`modal_id`）。因此**既不能靠"当前地址"、也不能靠"第一个 video"**确定目标。

链路：

1. **选主播放器**——在页面所有 `<video>` 中选出当前正在播放的那一个。
2. **收集身份信号**（按优先级）：`data-aweme-id` → `data-video-id` → 容器 `className` → 当前地址。
3. **拼视频 ID**；取不到就**丢弃该候选**，不上报。
4. **规范化地址**为 `https://www.douyin.com/video/<id>`。
5. **分流**：若主播放器已有直连媒体地址（非 blob），直接用直连流下载；否则把规范化地址交给桌面端走 yt-dlp 页面解析。

第 5 步的分流决定了后续是否需要合并音视频：直连流通常是合轨，页面解析返回独立音轨。

## 3. 字段映射

| 候选字段 | 来源 |
| --- | --- |
| 标题 | `昵称 - 描述`；缺任一时退化为 `抖音视频 <id>` |
| 页面地址 | 规范化后的 `https://www.douyin.com/video/<id>` |
| 清晰度 | 直连流取播放器 `videoHeight`；页面解析取 yt-dlp 结果 |
| 音轨 | 直连流为合轨；页面解析为独立音轨，**需合并** |
| 归组键 | `douyin:<id>` |

## 4. 与通用路径的差异

| 项 | 通用 | 抖音 | 原因 |
| --- | --- | --- | --- |
| 上报前提 | 必须有 blob 源 | **允许直连流** | 抖音部分内容直接给出可下载地址，没有 blob |
| 播放器 | 全部上报 | **只上报主播放器** | 信息流页面同时挂着多个 video，全报会产生大量错误候选 |
| 身份 ID | 可选 | **必需** | 无 ID 无法归组，也无法规范化地址 |
| 页面约束 | 无 | 必须能取出 10–30 位数字 ID | 详情页只有这一种形态 |

**放宽 blob 约束是有代价的**：通用路径靠 blob 源排除广告与预加载资源，抖音放宽后必须靠"必须有 ID"兜底。**这两条不能同时去掉**。

## 6. 验证方法

### 手工

1. 打开抖音某视频详情页 → 扩展候选数 ≥ 1，标题为「昵称 - 描述」形态。
2. 打开抖音首页信息流，滚动若干条 → **只上报当前播放的那一条**。
3. 刷新页面后立即下载 → 不出现 `douyin_session_expired`。
4. 点击"下载" → 桌面端完成下载，文件名与标题一致。
