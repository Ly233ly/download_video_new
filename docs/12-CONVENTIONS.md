# 12 · 工程约定

本文定义代码结构、命名、错误处理、日志、测试与提交规则。

---

## 1. 目录与包

### 1.1 职责

| 目录 | 职责 | 禁止 |
| --- | --- | --- |
| `cmd/` | 可执行入口，只做装配与依赖注入 | 含业务逻辑 |
| `internal/` | 私有实现 | 被工作区外导入 |
| `frontend/` | Web 前端 | 直接访问文件系统/进程/注册表 |
| `extension/` | 浏览器扩展 | 引入构建步骤 |
| `build/` | 构建脚本 | 含运行时代码 |
| `adapters/` | 站点适配器声明与站点文档（唯一事实源） | 写公共发现逻辑（[14](14-SITE-ADAPTERS.md)） |
| `design/` | 界面设计稿与设计稿自检（**不参与构建**） | 被 `frontend/` 引用为运行时资源 |

`design/_check.mjs` 是**设计稿自检脚本**，职责与限制见 [09 §4.2](09-UI.md)，此处不重复。它是防止"文档与设计稿各写一套值"的机械手段（设计原则 3），改了设计稿或改了 09 §4 之后都要跑一次。

> 该脚本在阶段 1 用真实前端工程重建设计系统后即可退役；届时它的职责由 §10 `Z3` 的契约校验脚本承接。

### 1.2 包划分

见 [01 §3](01-ARCHITECTURE.md)。包名必须与职责一一对应，**禁止**出现 `utils`、`common`、`helpers` 这类无边界包。

### 1.3 依赖方向

```text
cmd → internal/*
internal/* → internal/platform
任意 → （尽量少的外部依赖）
```

**禁止**循环依赖。

## 2. 命名

| 对象 | 约定 | 示例 |
| --- | --- | --- |
| 包 | 小写单词，无下划线 | `capture`, `media`, `store` |
| 文件 | 小写下划线，按职责 | `plan_state.go`, `proxy_restore.go` |
| 导出标识符 | PascalCase | `PlanCoordinator` |
| 非导出标识符 | camelCase | `resolveTool` |
| 接口 | 名词或 `-er` 后缀 | `RestoreStore`, `ToolResolver` |
| 常量 | PascalCase | `MaxPackageBytes` |
| 错误变量 | `err` 前缀 | `errPlanNotRetryable` |
| 测试 | `Test<被测>_<场景>` | `TestPlanStop_DoesNotOverwriteCanceled` |
| 前端组件 | PascalCase 文件（扩展名随阶段 1 定下的框架） | `PlanList` |

**契约标注**：只在实现**关键外部行为**（文件删除、代理恢复、秘密边界）的函数上标注契约编号，例如 `// B-402`。**不做机器扫描，不要求全覆盖。**

## 3. 错误处理

### 3.1 错误码

- 错误码是**稳定枚举**，一经发布不得改变语义。
- 清单见 [05 §7](05-DOWNLOAD.md)、[08 §9](08-EAGLE-IDM.md)。
- 面向用户的错误必须映射为**可安全展示的中文消息**。

### 3.2 分类与处理

| 类别 | 处理 |
| --- | --- |
| 输入错误 | 返回明确错误码，不重试 |
| 可重试错误 | 有界退避重试 |
| 环境错误 | 降级或等待，不终止进程 |
| 编程错误 | 记录并 panic（仅限启动期） |

### 3.3 禁止

| # | 禁止 |
| --- | --- |
| E1 | 吞掉错误 |
| E2 | 把原始错误或堆栈展示给用户 |
| E3 | 在错误消息中包含路径、URL 或秘密 |
| E4 | 无超时的网络、进程或数据库调用 |
| E5 | 用错误信息做流程控制 |

## 4. 日志

### 4.1 结构化日志

使用标准库 `log/slog`，字段固定：

| 字段 | 说明 |
| --- | --- |
| `level` | 级别 |
| `time` | 时间戳 |
| `component` | 子系统（`media`、`capture`、`api`…） |
| `event` | 事件名 |
| `code` | 错误码（若适用） |
| 上下文 | 任务 ID、计划 ID 等**非敏感**标识 |

### 4.2 级别

| 级别 | 用途 |
| --- | --- |
| `Debug` | 开发诊断，默认关闭 |
| `Info` | 生命周期事件（启动、捕获启停、任务完成） |
| `Warn` | 可恢复异常、降级 |
| `Error` | 操作失败 |

### 4.3 禁止记录

**日志中不得出现任何秘密**（Cookie、`Authorization`、完整签名 URL、`decode_key`、解密键）。

路径可以出现在**本地日志**中便于排错，但**不得出现在诊断导出**与用户可见错误消息中。

### 4.4 性能记录

关键操作记录耗时，默认阈值 **50 ms**，超阈值记一条结构化事件。

### 4.5 轮转

按大小轮转，保留上限默认 **10 MB × 5 个文件**，避免无限增长。

## 5. 测试

### 5.1 层次

| 层 | 位置 | 内容 |
| --- | --- | --- |
| 单元 | 与实现同包 | 纯函数、状态机、规则判定 |
| 契约 | `internal/<pkg>/*_test.go` | 每条 B 契约的对应测试 |
| 集成 | `tests/` | 跨组件、真实文件系统与数据库 |
| 矩阵 | `tests/` 脚本 | [11 §2](11-ACCEPTANCE.md) 的回归矩阵 |

### 5.2 要求

| # | 要求 |
| --- | --- |
| T1 | 测试命名可追溯到契约编号或测试 ID |
| T2 | 使用临时目录，不污染用户目录 |
| T3 | 网络测试使用本地假服务，不依赖外网 |
| T4 | 时间相关逻辑可注入时钟 |
| T5 | 视频号解密必须有公共领域测试向量 |
| T6 | 数据库测试覆盖结构初始化与约束 |

### 5.3 禁止

- 测试之间共享可变全局状态
- 依赖执行顺序
- 跳过失败测试而不记录原因

## 6. 提交与门禁

### 6.1 提交信息

格式：`<类型>(<范围>): <描述>`

| 类型 | 用途 |
| --- | --- |
| `feat` | 新能力 |
| `fix` | 修复 |
| `docs` | 文档 |
| `refactor` | 重构（行为不变） |
| `test` | 测试 |
| `build` | 构建与依赖 |
| `chore` | 杂项 |

### 6.2 提交前必须通过

| # | 门禁 |
| --- | --- |
| 1 | 格式化与静态检查 |
| 2 | 全部单元与契约测试 |
| 3 | 扩展 JS 语法检查 + 两份清单 JSON 解析 |
| 4 | 前端类型检查与构建 |
| 5 | 文档同步检查（见 §7） |
| 6 | 站点适配器构建产物与 `adapters/` 一致 |

### 6.3 生成物

以下文件由构建生成，**禁止手工编辑**——改了也会被下次构建覆盖：

| 生成物 | 来源 | 说明 |
| --- | --- | --- |
| `extension/site-adapters.json` | `adapters/` | 扩展所需的适配器字段副本（[14 §4](14-SITE-ADAPTERS.md)） |

生成物**必须**带 `"generated": true` 与来源标记，便于识别误改。

## 7. 文档同步

**规则**：**行为或架构边界**变更必须同步文档。普通实现细节、内部重构、缺陷修复**不需要**。文档与实现冲突时，先改文档再改代码。

| 变更类型 | 必须同步 |
| --- | --- |
| 新增/变更契约 | [02](02-BEHAVIOR.md) + [11](11-ACCEPTANCE.md) 矩阵 |
| 结构变更 | [03](03-DATA.md) |
| 接口变更 | [04](04-INTERFACES.md) |
| 界面变更 | [09](09-UI.md) |
| 发行流程变更 | [10](10-DISTRIBUTION.md) |
| 架构决策变更 | **新增 ADR**，不修改已接受的 ADR |
| 适配器变更 | [14](14-SITE-ADAPTERS.md) + `adapters/<id>/README.md` |

## 8. 版本与依赖

### 8.1 版本

| 项 | 规定 |
| --- | --- |
| 当前版本 | `2.0.0` |
| 版本位置 | Go 常量、前端清单、两份扩展清单、安装器资源、构建脚本 |
| 一致性 | 提交前自动校验全部位置一致（T-BRAND-03） |

### 8.2 依赖

| 项 | 规定 |
| --- | --- |
| 允许 | 第三方依赖 |
| 要求 | 每个依赖必须有明确用途与许可证 |
| 锁定 | `go.mod` + `go.sum`（校验和）与 `package-lock.json` |
| 工具链 | Go 版本在 `go.mod` 的 `toolchain` 指令中声明 |
| 审查 | 新增依赖必须在提交信息中说明理由 |
| 禁止 | 引入与既有能力重复的大型框架 |

> `go.sum` 只记录校验和，**不是**依赖选择清单；依赖版本与工具链版本以 `go.mod` 为准。

### 8.3 外部工具版本

FFmpeg、FFprobe、yt-dlp、Deno 固定版本并记录校验和（[10 §5.4](10-DISTRIBUTION.md)）。

## 9. 禁止事项

| # | 禁止 |
| --- | --- |
| C1 | 无主的 goroutine / 未管理的异步任务 |
| C2 | 无超时的跨边界调用 |
| C3 | 无界队列或缓存 |
| C4 | 在日志、错误、事件中泄露秘密 |
| C5 | 未持有恢复凭据时改写系统代理 |
| C6 | 删除或修改归属不明的文件 |
| C7 | 绕过行为契约的任何条目 |
| C8 | 在 `frontend/` 直接操作文件系统、进程或注册表 |
| C9 | 引入构建步骤到浏览器扩展 |
| C10 | 修改旧项目 `E:\Users\MSI\Desktop\codex_download` |
