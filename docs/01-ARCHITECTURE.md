# 01 · 架构规格

本文定义进程模型、通信方式、目录结构、并发模型与生命周期时序。

---

## 1. 进程模型

产品由**四个可执行文件**组成。

```text
┌─ 留底下载器.exe（主程序，常驻）─────────────────────┐
│  UI 层（WebView2 渲染 frontend 构建产物）           │
│  绑定层（前端 ↔ Go 方法与事件）                     │
│  本地 API（回环，供扩展）                          │
│  下载引擎（计划、下载、合并、校验）                  │
│  数据层（SQLite）                                  │
│  后台循环（IDM 入库、Eagle 补导、缓存维护）          │
│  系统托盘与生命周期                                │
│  捕获守护（子进程管理与代理恢复）                    │
└───────────────────────────────────────────────────┘
        │ 管道 JSON-RPC（按需启动）
        ▼
┌─ liudi-capture.exe（仅捕获时存在）─────────────────┐
│  HTTPS 中间人代理（仅回环监听）                     │
│  证书管理 · 页面 bridge 注入 · 候选上报             │
└───────────────────────────────────────────────────┘

┌─ IdmEagleHook.exe（IDM 调用，短命）───────────────┐
│  只做两件事：写一个文件到 inbox/，发一个命名事件     │
└───────────────────────────────────────────────────┘

┌─ 留底安装器.exe（独立单文件）─────────────────────┐
│  安装 · 升级 · 回滚 · 卸载                         │
└───────────────────────────────────────────────────┘
```

### 1.1 为什么捕获代理是独立进程

| 理由 | 说明 |
| --- | --- |
| 崩溃隔离 | 代理涉及 TLS 终止与系统代理改写，是最易出错的部分 |
| 可恢复 | 子进程崩溃时父进程还活着，能立即恢复代理 |
| 权限隔离 | 证书操作局限在子进程 |
| 可独立测试 | 代理可脱离桌面端单独运行 |

**关键区别**：父进程不持有"租约文件"，也不需要判定"代理是不是我写的"。父子进程关系本身就是身份——**子进程一死父进程立刻知道**。

### 1.2 为什么 hook 不做成"微型下载器"

hook 不碰数据库、不开 API、不做协议。它只：

1. 把收到的文件路径写进 `inbox/<时间戳>-<随机>.json`
2. 发送命名事件 `Local\LiudiWake`
3. 退出

主程序监听 inbox 目录并消费。这使 hook 的复杂度与可靠性风险降到最低。

## 2. 通信方式

| # | 通道 | 方式 | 认证 | 理由 |
| --- | --- | --- | --- | --- |
| C1 | UI ↔ Go | Wails 绑定 + 事件 | 同进程 | 无需认证 |
| C2 | 扩展 ↔ Go | 回环 HTTP | **仅 Origin 白名单** | 无登录、无配对 |
| C3 | Go ↔ 捕获子进程 | **管道 JSON-RPC** | 父子关系 | 不开端口，EOF 即感知 |
| C4 | 网页 bridge → 捕获 | 代理拦截 `/__liudi/report` | 无 | 代理本就看得到该请求 |
| C5 | hook → Go | inbox 文件 + 命名事件 | 本地目录 | 极简 |

### 2.1 C2：Origin 白名单

本地 API 只接受来自本扩展的请求：

```text
允许：Origin == "chrome-extension://<固定扩展 ID>"
其余：403
```

扩展 **manifest 中固定 `key` 字段**，使 ID 在开发者模式与打包后保持一致（Chrome 官方机制）。该 ID 以**编译常量**形式内置到桌面端，**无需安装器写入任何配置**。

若需要临时用其他 ID 调试，可通过设置项覆盖。

**不包含**：配对码、bootstrap 秘密、令牌签发/失效/恢复流程。

### 2.1.1 本地 API 必须自建 `net/http`（**不可复用 Wails AssetServer**）

这是一条**已查证、且极易搞错**的硬性约束：

| 事实 | 后果 |
| --- | --- |
| Wails v2 的 `AssetServer` **不是 TCP 监听器**，而是 `http.Handler`，由 WebView2 的资源拦截事件喂入 | 它只服务**自己渲染的页面** |
| 它匹配的虚拟 origin 是 `http://wails.localhost/`（Windows 上无法用 `wails://`） | **外部浏览器扩展的请求永远进不来** |
| 它明确不支持 WebSocket，Windows 上响应体流式也标为不支持 | 连给自家前端做流式 API 都不合适 |

**因此**：`127.0.0.1:47652` 的本地 API 必须自己起 `net/http` Server。

| # | 要求 |
| --- | --- |
| S1 | 绑定地址写 **`127.0.0.1:<端口>`**，**不得**写 `:端口`（会监听全部网卡并触发防火墙弹窗），也**不得**写 `localhost`（IPv4/IPv6 解析有歧义） |
| S2 | 在 `OnStartup` 中 `go srv.ListenAndServe()`，`*http.Server` 存入 app 结构体 |
| S3 | 在 `OnShutdown` 中 `srv.Shutdown(ctx)` 优雅关闭；**不得**让退出直接把连接硬切 |
| S4 | 端口被占用时回退临时端口，并把**实际端口**写到约定位置：`%LOCALAPPDATA%\LiudiDownloader\api-port.json`，内容 `{"port":47652,"pid":1234}`。写入时机是服务开始监听之后；扩展按该文件的 `pid` 校验进程仍在再使用端口 |
| S5 | 超时按「`ReadHeaderTimeout` 5–10 s、`IdleTimeout` 60–120 s、**`ReadTimeout` / `WriteTimeout` 设 0**」配置；需要闲置上限就用 `http.ResponseController` 续期，而不是给整条连接设死写超时 |
| S6 | 中转上传端点必须**流式落盘**——`io.Copy(dst, r.Body)` 或读循环，**禁止** `io.ReadAll` |
| S7 | 用 `http.MaxBytesReader` 按分片上限硬性拒绝，**读到超限即刻返回，不等读完整个请求体** |

> **关于是否要加本地令牌**：不加。本机其他进程能访问该端口属于"防攻击者"范畴，而我们的对手是自己出的 bug（ADR-003）。**不得**重新引入令牌机制，除非能回答「它解决了用户实际遇到的什么问题」。

### 2.2 C3：管道 JSON-RPC

```text
父 → 子：{"id":1,"method":"start","params":{...}}\n
子 → 父：{"id":1,"result":{...}}\n
          {"event":"candidate","data":{...}}\n
```

- 行分隔 JSON，一条一行
- 父进程写 stdin、读 stdout；子进程 stderr 只用于日志
- **父进程退出 → 子进程 stdin EOF → 子进程自行退出**
- **子进程崩溃 → 父进程 read 失败 → 立即恢复代理**

### 2.3 C4：bridge 上报

注入到微信内嵌页面的 bridge 向**同源路径** `POST /__liudi/report` 发送数据。

捕获代理识别该路径后：

- **不转发**给上游
- 直接解析并转成 C3 事件发给父进程

这样无需额外端口，也不存在"网页拿到内部令牌"的问题。

## 4. 并发模型

**禁止无主的 `go func()`。** 一切并发任务必须可取消、可等待、有界。

| 场景 | 模型 |
| --- | --- |
| UI → 后端 | Wails 绑定调用，在 goroutine 中执行，结果经事件回推 |
| 后台循环 | 单个长驻 goroutine，由命名事件与定时器（≥1 s）驱动 |
| 批量下载 | `errgroup` + 加权信号量，并发上限来自配置 |
| 单个下载 | 独立 goroutine，持有 `context.Context` |
| 数据库写入 | 直接使用 SQLite 事务，不引入单写者队列——理由见 [03 §1](03-DATA.md) 的 `P2` |
| 外部工具 | 每进程有超时与 `context` 取消；健康探测用 single-flight |
| 捕获子进程 | 一个读 goroutine（stdout）+ 写串行化；父进程等待句柄 |

### 4.1 前端不轮询

界面状态变化**全部由事件推送**驱动，取代旧实现按固定间隔重绘的做法。

主进程内部允许存在低频兜底定时器，但周期**不得小于 1 秒**，且不得承担状态同步的主要职责。

## 5. 生命周期时序

### 5.1 启动

顺序**不可调换**：

```text
1. 单实例互斥体检查
     → 已有实例：发唤醒事件并退出
     → 无实例：继续
2. 【最高优先级】检查代理残留
     → 存在恢复凭据：恢复系统代理后再继续
     → 此步骤不依赖数据库、配置或 UI
3. 打开数据库（初始化或版本校验）
4. 读取配置（配置的唯一权威源是数据库 settings 表）
5. 启动本地 API（回环）
6. 消费 inbox/ 残留（上次未处理的 IDM 文件）
7. 启动后台循环
8. 启动 Wails UI
```

**第 2 步必须最先执行**：数据库损坏或版本过新都可能让后续步骤终止，那时用户会带着一个失效的系统代理断网。

### 5.2 关闭

```text
1. 停止接收新任务
2. 取消在途下载（保留可恢复状态）
3. 停止捕获子进程并恢复代理
4. 关闭本地 API
5. 刷写数据库并关闭
6. 退出
```

每一步有独立超时，**任一步超时都不得阻塞后续步骤**。代理恢复必须在自己超时预算内完成。

### 5.3 异常退出恢复

**所有"有界"都必须有具体秒数**，不得留作形容词：

| 环节 | 上限 | 超限处置 |
| --- | --- | --- |
| 关闭/退出总预算 | **10 s** | 超预算强杀子进程 |
| 关闭时的单个步骤 | **2 s** | 跳过该步并记日志，继续下一步 |
| 优雅终止后等待回收 | **2 s** | 强杀 |
| 代理恢复（含崩溃与兜底路径） | **3 s** | 报错并提示用户手动检查系统代理 |
| `srv.Shutdown(ctx)`（本地 API） | **3 s** | 关闭连接，不阻塞退出 |

> 这些值是**上限而非目标**：正常路径应在毫秒级完成。它们的存在是为了保证"退出一定能退出、断网一定能恢复"。

| 场景 | 处理 |
| --- | --- |
| 主进程被强杀、断电 | 下次启动第 2 步恢复代理 |
| 捕获子进程崩溃 | 父进程 read 失败 → 立即恢复代理 → 推送事件 |
| 子进程挂死未退出 | 父进程超时后强杀，再恢复代理 |

## 6. 代理恢复机制

这是"用户不因程序故障断网"的实现。

### 6.1 写入流程

```text
1. 读取当前系统代理设置（ProxyEnable / ProxyServer / ProxyOverride / AutoConfigURL）
2. 保存到 %LOCALAPPDATA%\LiudiDownloader\proxy-restore.json
     含 original（原值）与 applied（本程序写入值）两组
3. 写入系统代理指向回环捕获端口（**默认 `47653`**；被占用时回退临时端口，实际值随快照一起记录，因为 `applied` 值必须含端口）
```

**同时保存 original 与 applied 是必要的**：恢复时要能判断"当前值是不是我们写的"。

### 6.2 恢复流程

```text
1. 读 proxy-restore.json
     → 不存在：无操作，结束
2. 读当前系统代理值
3. 若 当前值 == applied  → 写回 original
   否则                  → 不覆盖（其他软件已改），仅记录
4. 删除 proxy-restore.json
```

### 6.3 硬性要求

| # | 要求 |
| --- | --- |
| P1 | 恢复必须在启动的**第 2 步**执行，不依赖数据库与配置 |
| P2 | 恢复失败必须保留 restore 文件并给出用户可见提示 |
| P3 | 恢复在独立超时内完成，不阻塞退出 |
| P4 | 未持有 restore 文件时**绝不**改写系统代理 |
| P5 | 停止捕获、退出、升级、卸载都必须执行恢复 |

## 7. 性能设计

针对旧实现的三个根因。

### 7.1 界面响应

| 措施 | 要求 |
| --- | --- |
| 事件驱动 | 前端不轮询 |
| 虚拟滚动 | 长列表 DOM 节点数有上界 |
| 增量更新 | 单条变化只更新对应行，不重建容器、不重置滚动 |
| 有界查询 | 详见 [03 §5](03-DATA.md) 的查询约束，本文不重复 |
| 主线程卸载 | IO、进程、哈希、解密全在 Go 侧异步 |

### 7.2 捕获代理吞吐

| 措施 | 要求 |
| --- | --- |
| 原生 TLS | Go 标准库 TLS 栈 |
| 流式转发 | `io.Copy` + `bufio`，大响应不整体缓冲 |
| 连接复用 | 上游连接池 |
| 绕过前置 | 媒体 CDN 主机在**建立连接前**判定绕过 |
| 背压 | 转发受 `context` 与超时约束 |

### 7.3 调度

| 措施 | 要求 |
| --- | --- |
| 并发上限 | 全局与单类任务各有信号量，配置化 |
| 优先级 | 用户可见任务优先于缓存维护、补导 |
| 写入节流 | 高频进度写入节流落库（默认 500 ms），避免写放大 |
| 无忙等 | 空闲时 goroutine 阻塞在 channel/事件上，CPU 接近 0 |


## 9. 禁止事项

| # | 禁止 |
| --- | --- |
| N1 | 在 `frontend/` 直接操作文件系统、进程或注册表 |
| N2 | 在捕获子进程中实现下载、数据库或 Eagle 逻辑 |
| N3 | 无 `context` 的网络与进程调用 |
| N4 | 无主 goroutine、无界队列、无超时等待 |
| N5 | 在日志、错误、事件载荷中泄露 Cookie 与签名 URL |
| N6 | 未持有恢复凭据时改写系统代理 |
| N7 | 删除或修改归属不明的文件 |
| N8 | 修改旧项目 `E:\Users\MSI\Desktop\codex_download` |
| N9 | 在 HTTP handler 或 Wails binding 中编写业务逻辑（必须经 Service 层，见 [04 §1.2](04-INTERFACES.md)） |
| N10 | 用 Wails `AssetServer` 承载扩展 API（它对外不可达，见 §2.1.1） |
| N11 | 对中转上传使用 `io.ReadAll` 或把整个文件读进内存 |
| N12 | **重新引入已删除的协调机制**：配对码、令牌签发/轮换/恢复、bootstrap 秘密、租约归属判定、数据库单写者队列、实体事件版本协议、SSRF 每跳校验、更新器自动健康检查与回滚、候选三表持久化、迁移链。除非能回答「它解决了用户实际遇到的什么问题」（设计原则 1） |

> **N12 的清单为什么不写在各处**：这些机制是**简化两轮被删掉的**，删除理由与替代方案记录在 [ADR-003](adr/ADR-003-simplified-security.md)。本文只留禁令，不重复那段历史——重复的历史会随改动漂移，而禁令不会。
