# 06 · 视频号捕获

本文定义微信视频号捕获子系统的架构、身份绑定、画质策略与验收边界。

---

## 1. 定位

| 项 | 规定 |
| --- | --- |
| 默认状态 | **关闭**，只能由用户明确启动（B-701） |
| 进程 | 独立子进程 `liudi-capture.exe`（[01 §1.1](01-ARCHITECTURE.md)） |
| 通信 | **管道 JSON-RPC**（[04 §5](04-INTERFACES.md)） |
| 监听 | 只监听回环地址（B-703） |
| 不负责 | 下载执行、数据库、Eagle |
| DRM | 只识别提示，不绕过 |
| 站点适配器 | 本捕获链对应 `adapters/wechat-channels/`（[14](14-SITE-ADAPTERS.md)）；域名匹配与优先级由适配器声明，不在捕获代码里硬编码 |
| 浏览器下载模式 | **不适用**。该模式下浏览器取到的仍是加密字节，缺会话密钥无法解密；弹窗开启该模式时视频号入口保持原逻辑并提示（B-226） |

> ⚠️ **难度量级与其他站点完全不同，根因在这里**：[yt-dlp](15-UPSTREAM.md)（934 个站点提取器）**不支持视频号**——941 个提取器里没有 wechat / weixin / channels / finder / sph 任何一项。
>
> 这意味着其他站点（含抖音）都有"拿到 URL 就能解析"的上游可用，而视频号**没有解析器可依**：捕获、身份绑定、解密、画质策略**全链路必须自研**。这是 M5 至今未通过的结构性原因，不是实现质量问题。

## 2. 架构

```text
用户点击「开始捕获」
  → 主进程：读取并保存系统代理快照（original + applied）
  → 主进程：校验上游可解析性（不安全则在改代理前失败）
  → 主进程：启动 liudi-capture.exe（管道）
  → 子进程：装载/校验根证书，监听回环端口，输出 ready
  → 主进程：收到 ready 后才写入系统代理
  → 子进程：向微信页面注入 bridge
  → bridge：读取微信自身返回的 feed 与详情，POST /__liudi/report
  → 子进程：校验并转成 candidate 事件上报主进程
  → 用户：页内按钮或桌面候选页提交（统一调用 `PlanCreateFromCandidate`，后端从内存候选取地址与解密信息）
  → 主进程：下载、解密、封装、校验、交付
  → 用户点击停止 / 退出 / 升级 / 卸载
  → 子进程退出；主进程恢复代理、删除恢复文件并推送状态
```

### 2.1 TLS 终止范围

| 目标 | 处置 |
| --- | --- |
| 视频号页面与脚本 | **终止 TLS**，注入 bridge |
| `finder.video.qq.com` 及子域 | **拒绝终止**，写入绕过列表（B-704） |
| 其他 HTTP / HTTPS | 透明转发 |
| `/__liudi/report` | **拦截**，不转发，转成事件 |

**禁止**：为收集请求头而代理、预热或提前消费媒体 URL（B-706）。

## 3. 证书

| 阶段 | 要求 |
| --- | --- |
| 生成 | 首次捕获时生成根证书与私钥 |
| 存放 | `%LOCALAPPDATA%\LiudiDownloader\certs\` |
| 私钥权限 | 只允许当前用户读取 |
| 安装 | 只装到 `Cert:\CurrentUser\Root`，**必须**由用户亲自确认 Windows 警告（B-702） |
| 名称 | 留底下载器 微信视频号本机捕获根证书 |
| 复用 | 已安装且指纹匹配则跳过 |
| 移除 | 卸载时按**指纹精确**删除，绝不触碰其他证书 |
| 失败 | 必须中止捕获并恢复代理，不得"捕获继续但证书无效" |

## 4. bridge 与上报

bridge 由子进程注入视频号页面，职责：

| 职责 | 说明 |
| --- | --- |
| 读取 feed | 从微信**自身已返回**的数据中提取，不主动请求 |
| 登记候选 | `objectId`、标题、作者、封面、时长、媒体地址、质量规格 |
| 绑定当前项 | 按 §5 的强证据规则 |
| 注入下载入口 | 页面操作栏的下载按钮与下拉菜单 |
| 上报 | `POST /__liudi/report`（同源路径，代理拦截） |

### 4.1 上报格式

```json
{ "kind": "candidate", "session": "<会话标识>", "payload": { ... } }
```

| 要求 | 规定 |
| --- | --- |
| 会话绑定 | 请求必须带子进程签发的 `session`，与当前捕获会话匹配 |
| 字段白名单 | 子进程只接受已知字段，其余丢弃 |
| 长度上限 | 请求体 ≤ 256 KB |
| 防重放 | 子进程只接受当前会话的标识；会话变更后旧标识失效 |

**bridge 不持有任何内部令牌**——它能调用的只是这个被拦截的同源路径。

### 4.2 页面脚本升级

脚本升级后**必须重新进入视频号页面**才能加载新版逻辑；仅拖动进度不会重新注入。界面必须提示这一点。

## 5. 当前视频绑定

候选可登记任意多个，但**只有当前内容可激活与提交**。

### 5.1 强证据（五选一或组合）

1. 页面或当前卡片白名单属性中的唯一 `objectId`
2. 媒体路径 + 稳定 `encfilekey`
3. 视口内唯一且正在播放的视频元素，与权威详情主对象的短期绑定
4. 当前视频元素的唯一 `poster` 封面
5. 当前卡片中规范化后的完整标题

### 5.2 冲突处理

证据冲突时**一律拒绝**（B-707）。以下**不能**单独授权下载：

作者、时长、地址栏残留 ID、候选数量、接口返回时间、"最后到达的一条"。

### 5.3 共用 CDN 路径

微信大量视频共用 `/stodownload`。此类地址**必须同时匹配内存中的 `encfilekey`**（B-709）。

- 短期 `token` / `sign` 轮换不影响身份。
- 不含 `encfilekey` 的通用路径**不构成身份**，即使内存中只有一个候选也不得猜测。

### 5.4 `blob:` 地址

MSE 播放器可能只暴露 `blob:`。bridge 只把权威当前详情绑定到视口内**唯一**的播放元素，并在 `loadstart`、`emptied` 或实际时长改变时**清除旧绑定**（B-710）。

### 5.5 详情响应中的推荐

`finderGetCommentDetail` 可能返回主视频 + 数十条推荐。

| 情况 | 处置 |
| --- | --- |
| `data.object` 只有一个可归一化 ID | 允许绑定 |
| 推荐列表任意数量/顺序 | 只登记候选 |
| `data.object` 缺失或含两个不同 ID | **拒绝** |

## 6. 画质策略

### 6.1 档位模型

视频号对外暴露的画质档位语义上只有两类：

| 档位 | 含义 |
| --- | --- |
| `original` | 原画（真实高清源） |
| 明确转码档（如 `xWT111`） | 转码档；720p 通常对应此档 |

feed 中的 `spec` 数组描述各档的分辨率、码率与大小等元数据。

### 6.2 选择规则

```text
若存在可通过验真的原画候选 → 选原画
否则 → 在明确档中按（分辨率, 码率, 大小）排序取最高
```

| # | 约束 |
| --- | --- |
| C1 | **不得**跟随播放器的 720p 转码档降级（B-712） |
| C2 | 无原画时只能**如实**交付最高明确转码，不得标注为高清（B-723） |
| C3 | 「原视频」名称、feed 元数据、接口 HTTP 成功**都不构成**高清命中（B-714） |
| C4 | 高清命中的唯一判据是真实 FFprobe：`max(w,h) > 1280` 且 `min(w,h) > 720`（B-713） |

### 6.3 原画地址的合法来源

| 来源 | 说明 |
| --- | --- |
| 同一内部响应中的配对地址 | URL + `decode_key` + feed 声明大小同响应取得 |
| 页面重新签发的完整地址 | 完整保留 `basedata`、`sign`、`hy`、`idx` 等参数 |

**禁止**：通过 TLS 中间人读取媒体 CDN 请求头；只修改画质参数合成地址；预热或提前消耗可能一次有效的 URL（B-706、B-715）。

### 6.4 原画获取的外部观察（待真机验证）

以下来自对同类开源项目的**行为观察**，**尚未在本机验证**，作为待验证假设：

| # | 假设 | 验证方式 |
| --- | --- | --- |
| H1 | 画质档位只有 `original` 与转码档两种 | 抓取本机 feed，枚举 `spec` 取值 |
| H2 | feed 对象携带 `original_url` 字段，可直接透传 | 抓取本机 feed，检查该字段存在性与指向 |
| H3 | 原画入口存在于**视频详情页的「更多」菜单**，而非首页信息流 | PC 微信详情页观察是否存在该入口 |
| H4 | 原画请求失败可能由**出口 IP 段**导致，而非签名问题 | 报错时做换网络出口的对照实验 |
| H5 | 存在 `originalInfo` 结构随对象扩展返回 | 抓取本机响应，检查该字段 |

**合规约束**：H1–H5 是**行为观察**，不是代码参考。实现必须独立完成，**不得移植**他人源码或常量。验证证据只能是抓包得到的真实请求与响应。

**若 H2 或 H3 成立**，优先方案是**直接读取并透传微信签发的原画地址**，而不是自行构造参数。

### 6.5 `X-snsvideoflag`

大小写不敏感替换，且**只能存在一次**。

## 7. 代理与上游

### 7.1 上游解析优先级

1. 可安全解析的 PAC / WPAD
2. 已启用的 WinINET HTTP / Mixed 代理
3. 留底保存的 HTTP / Mixed 代理
4. 直连

### 7.2 安全前置

**上游无法安全解析时，必须在改写系统代理之前失败**（宁可捕获启动失败，也不能让用户断网）。

### 7.3 绕过列表

| 项 | 规定 |
| --- | --- |
| `finder.video.qq.com` 及子域 | **必须**写入绕过（B-704） |
| VPN 绕过列表中的明确主机与网段 | 继续生效 |
| 独立全局 `ProxyOverride=*` | **不参与**公共视频号域名判定 |

### 7.4 恢复

停止、退出、升级、卸载必须恢复程序仍拥有的代理设置（B-718）；其他软件后来修改的不得覆盖（B-719）。机制见 [01 §6](01-ARCHITECTURE.md)。

## 8. 解密与下载

### 8.1 前缀解密

微信视频号媒体为**加密 MP4**：前 **131072 字节**使用 ISAAC64 流密码加密，其余为明文。

| 要求 | 规定 |
| --- | --- |
| 算法 | ISAAC64 密钥流 XOR |
| 范围 | 仅前 131072 字节 |
| 实现 | 必须独立实现并有**公共领域测试向量** |
| 流式 | 必须流式解密，不得整文件入内存 |

**边界**：短于 131072 字节的文件、明文文件或变长前缀的处理方式必须在阶段 5 用样本确认（见 §12 `W8`）。

### 8.2 下载重试

| 情况 | 处置 |
| --- | --- |
| 首次 HTTP 400 | 可对同一地址用 `Range: bytes=0-` 重试**一次** |
| HTTP 400 / 403 | 可尝试同一签名资产的其他内存地址，但必须同时满足：主机/端口/路径一致、`encfilekey` 与 `token` 一致、字节数与 feed 声明完全一致 |
| 任一不满足 | 拒绝，不得把转码或低清标成原画 |
| 反复失败 | **同时做换出口对照**（验证 H4），排除 IP 因素后再判断签名问题 |

### 8.3 交付前置校验

见 [05 §6](05-DOWNLOAD.md)。失败即删除结果并报错，**不得降级交付 720p**。

## 9. 失败矩阵

| 现象 | 主要证据 | 处理 |
| --- | --- | --- |
| 开始捕获后黑屏、候选为 0 | 上游丢失或回环端口失效 | 继承可用上游；不可达时在改代理前停止 |
| Windows 指向已关闭的回环端口 | 代理开启但端口不监听 | 启动时检测并恢复（[01 §5.1](01-ARCHITECTURE.md) 第 2 步） |
| 有候选但「未能确认当前视频」 | 无 active、`blob:`、共用路径、详情带推荐 | 用稳定媒体标识与 `data.object` 唯一主对象绑定；歧义继续拒绝 |
| 页内下载了相邻视频 | 旧地址栏、预加载响应或最后到达的候选被误当当前 | 多证据聚合；冲突拒绝 |
| 默认或「原视频」始终 720p | 签发链只返回播放级资产，或高清入口未捕获 | 按 §6.4 验证假设；**不得**靠改 URL 参数冒充 |
| 原画 HTTP 400 / 403 | 精简地址丢签名参数、会话过期，**或出口 IP 被拒** | 先用完整签发地址；再有界重试；**同时做换出口对照** |
| `wechat_size_mismatch` | 返回字节与 feed 声明不同 | 拒绝低清/转码冒充原画 |
| `wechat_original_resolution_mismatch` | 字节通过但分辨率不符 | 删除结果，不交付 |

## 10. 诊断顺序

1. 先确认问题在**任务创建前**还是**创建后**。若为「未能确认当前视频」且无新计划，属页面身份绑定，不要用下载/解密解释。
2. 查看捕获状态、候选数、内部观察数。候选增加但无 active → 检查详情主对象与播放元素绑定。
3. 有计划时检查 `status`、`error_code`、`downloaded_bytes`、质量标签与阶段信息。
4. 网络错误记录：请求阶段、HTTP 状态、声明大小、实际字节。**不得**记录完整 URL、Cookie、解密键或签名值。
5. 完成后检查文件存在、至少一个视频轨、分辨率与时长与候选一致。
6. 停止后核对 WinINET 与 `proxy-restore.json` 是否已清除。
