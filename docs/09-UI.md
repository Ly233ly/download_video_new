# 09 · 界面规格

本文定义桌面界面的技术栈、信息架构、交互与性能要求。

**旧实现基线**：`ui.py`，8,570 行 Tkinter 手绘。

---

## 1. 技术栈

**前端框架与工程约定的唯一权威位置是 [16 · 前端框架规范](16-FRONTEND.md)**（React 19 / React Compiler / `@tanstack/react-virtual` / 渲染约束）。本文只列与界面设计相关的层，选型细节不在此重复（设计原则 3）。

| 层 | 选型 |
| --- | --- |
| 桌面壳 | Wails |
| 渲染 | 系统 WebView2 |
| 语言 | TypeScript |
| 构建 | Vite |
| 样式 | Tailwind CSS |
| 框架 | **React 19**（含 React Compiler；见 [16](16-FRONTEND.md)） |
| 长列表 | **`@tanstack/react-virtual`**，固定行高（见 [16 §4.5](16-FRONTEND.md)） |
| 图标 | lucide |
| 通信 | 只经 [04 §3/§4](04-INTERFACES.md) 的绑定方法与事件 |

**禁止**：前端直接进行文件系统、进程、注册表或网络操作。

> 本文 §4.4~§4.7 定义**设计 token 与控件**，[16 §4](16-FRONTEND.md) 定义**渲染纪律**（列表不整体重建、订阅粒度到行、虚拟列表固定行高）。两者是"长什么样"与"怎么渲染"的分工，判据统一在 [11](11-ACCEPTANCE.md)。

## 2. 信息架构

### 2.1 主导航

侧边栏，固定顺序：

| # | 页面键 | 显示名 | 职责 |
| --- | --- | --- | --- |
| 1 | `media` | **下载任务** | 默认页；下载计划列表与详情 |
| 2 | `wechat` | **视频号** | 捕获控制与候选 |
| 3 | `idm` | **IDM 导入** | 导入任务列表 |
| 4 | `settings` | **设置** | 代理、缓存、主题、更新、关于 |
| — | 分隔 | | |
| 5 | `diagnostics` | **导出诊断信息** | 诊断导出 |

### 2.2 常驻元素

| 元素 | 位置 | 要求 |
| --- | --- | --- |
| 连接状态 | 顶部栏 | 必须说明 Eagle 可用性（B-809） |
| 主题切换 | 侧边栏底部 | 文案随当前主题变化 |
| 活动指示 | 顶部 | 下载中任务数、捕获状态 |

### 2.3 页面切换

- 页面状态按页面键分别保留（滚动位置、筛选条件）。
- 切换页面**不得**重建整棵应用树。

### 2.4 扩展弹窗

浏览器扩展的弹窗与独立窗口**不属于本文范围**——其结构与渲染契约由 [07 §6.2](07-EXTENSION.md) 定义（`P-101 ~ P-110`），**呈现规范**由 §4.8 定义（标签页划分、设置项写法）。

两处必须保持一致的部分：

| 项 | 要求 |
| --- | --- |
| 主题色 | 与 §4.4 同一套取值 |
| 状态语义 | 与本文相同的措辞与颜色映射 |
| 空状态与错误文案 | 同一风格，不出现技术细节 |
| 列表渲染 | 扩展侧遵守 `P-101 ~ P-110`，**不得**沿用旧版的整体重建 |
| 视图划分 | **候选与任务必须分成两个标签页**，不得挤在同一屏（§4.8） |

## 3. 页面规格

### 3.1 下载任务（`media`）

| 区域 | 内容 |
| --- | --- |
| 摘要 | 活动任务数、总进度、缓存占用入口 |
| 列表 | 计划；**连续滚动，无分页控件**（B-310） |
| 行信息 | 标题、来源、质量标签、状态、进度、阶段说明 |
| 行操作 | 打开文件夹、打开文件、停止、重试、补导 Eagle、删除记录 |
| 详情 | 展开显示来源地址等技术信息 |

**要求**：

- 只有 `plan.status = completed` 显示 100%（B-312、B-313）。导入状态由任务列表单独展示，不改变计划进度。
- 「仅下载完成」显示最终路径，并提供打开文件夹与补导入口（B-309）。
- `failed` 状态必须显示错误码对应的中文消息与质量档位。
- 大量任务下刷新不得随历史线性恶化（B-808）。

### 3.2 视频号（`wechat`）

| 区域 | 内容 |
| --- | --- |
| 捕获控制 | 开始/停止、捕获状态、证书状态 |
| 候选列表 | 当前会话候选；**禁止显示媒体 URL 或解密信息** |
| 提示 | 脚本升级后需重新进入页面的说明 |

**要求**：

- 捕获默认关闭（B-701）。
- 证书确认必须由用户亲自完成，界面只引导（B-702）。
- 候选展示不得泄露 URL、`decode_key`、签名参数（B-722）。
- 画质标签必须如实：未经验证的"原画"不得标为高清（B-714、B-723）。

### 3.3 IDM 导入（`idm`）

| 区域 | 内容 |
| --- | --- |
| 任务列表 | 状态、来源、Eagle 状态 |
| 操作 | 打开文件、打开网页、附加来源、重试、清理记录 |

**要求**：

- Eagle 未连接时阻止来源远程更新，但保留其他操作。
- 等待 Eagle 的任务不得阻塞下载队列的可视状态（B-602）。

### 3.4 设置（`settings`）

| 分组 | 项 |
| --- | --- |
| 网络代理 | 模式（自动/直连/手动）、手动地址 |
| 文件管理 | 缓存统计（临时/预览/旧日志）、手动清理、自动保留期 `0–365` |
| 外观 | 主题切换 |
| 更新 | 版本、检查更新 |
| 关于 | 版本、许可证、源码获取说明 |

**明确不在此页的项**：

| 项 | 原因 |
| --- | --- |
| **浏览器下载模式开关** | 用户明确要求**只放在扩展弹窗内**（B-220、[07 §6.3](07-EXTENSION.md)）。设置页**不得**出现该开关，验收见 T-UI-08 |

**要求**：

- 周期刷新**不得覆盖**用户尚未保存的代理输入（B-806）。
- 保存失败必须留在当前页并给出可恢复提示。
- 保留期 `0` 关闭自动清理，但不影响手动清理。

### 3.5 诊断（`diagnostics`）

导出诊断快照，**必须经秘密过滤**（不含 Cookie、签名 URL、解密键）。

### 3.6 托盘与通知

**这是用户明确提出的要求（硬性要求 #3）：下载完成后走系统托盘气泡。**

| 项 | 规定 | 契约 |
| --- | --- | --- |
| 常驻 | 程序在托盘常驻；关闭主窗口不退出 | B-813 |
| 托盘菜单 | 显示主窗口、当前活动任务数与总进度、开始/停止捕获、退出 | — |
| 完成通知 | 下载完成弹气泡，含输出名；点击打开所在文件夹 | B-810 |
| 失败通知 | 同样通知一次；**每个计划只通知一次终态**，重试不刷屏 | B-811 |
| 批量任务 | 短时间内多个完成必须**合并**为一条（如「3 个任务已完成」），不得逐条弹 | B-811 |
| 通知礼仪 | 不抢焦点、不阻塞；系统关闭通知时静默降级，不报错 | B-812 |
| 视觉 | 通知用系统原生外观（Windows 通知中心），**不**自绘成 macOS 样式——它不属于应用窗口 | — |

> **与托盘无关的边界说明**：托盘图标、托盘菜单与系统通知属于**操作系统外壳**，保持 Windows 原生，不随本应用的设计系统变化（§4.1）。

## 4. 设计系统

### 4.1 视觉基调

| 项 | 规定 |
| --- | --- |
| 基调 | **浅色主调 + 白卡片 + 单一蓝色强调色**，靠留白与极轻阴影分层 |
| 强调色 | `#2f6df6`（深色 `#5b8dff`） |
| 圆角 | 窗口 14px · 卡片/弹窗 **12px** · 控件 7px |
| 质感 | 扁平：无材质与模糊效果。层次只由**留白 + 1px 描边 + 极轻阴影**表达 |
| 渐变 | **禁止整块渐变背景**；允许装饰性微渐变（应用顶栏底、logo、缩略图占位），且必须登记 token（§4.4） |
| 明确不做 | 自绘**系统窗口装饰**（交通灯）、无边框窗口、材质/模糊效果 |
| **窗口外壳** | **系统标题栏与窗口控制键由 Windows 提供，不自绘**。应用内部自己的那条顶栏叫「**应用顶栏**」（§4.6），两者不是一回事 |

> **术语必须分清**：`系统标题栏` 指窗口最外层那条（含最小化/最大化/关闭），我们**不碰**；`应用顶栏` 指应用内部内容区顶部那条 48px 的栏（品牌、连接状态、主题切换）。本规范其余各处提到"标题栏"时，如无特别说明均指**应用顶栏**。

> **历史**：曾评估过「macOS 原生取向」方案（含自绘红黄绿交通灯与 vibrancy 等效色板），**经用户否决**——用户明确要求"不好看，回到上一版的基础上改"。那套取值已从本文移除，**不得**重新引入。

### 4.2 一处事实，一处定义

本节是全部视觉 token 的**唯一权威定义位置**。

- 扩展弹窗、桌面端各页、`design/mockup.html` 都必须引用同一组值，**不得**各自写一份（[07 AD-9](07-EXTENSION.md)）。
- 实现期直接生成 CSS 自定义属性与 Tailwind 主题，两处共用同一个生成物。

| 交付物 | 说明 |
| --- | --- |
| `design/mockup.html` | 设计稿，静态 HTML，不参与构建。**布局层的权威**，见下方 |
| `design/_check.mjs` | 自检：校验设计稿**结构**（HTML 标签平衡、内联 JS 语法、CSS 变量闭合、深浅色覆盖），并**打印**设计稿内的 token 实际取值。**它不做断言**——token 是否与本节一致需人工比对；本节才是权威 |
| `design/mockup.v1-gray-blue.html` | 同一套基调的早期留底，仅作对照 |

**两层权威，各管一段**（2026-10-02 补：此前只写了 token 层，导致实现时漏掉布局层）：

| 层 | 权威位置 | 覆盖内容 |
| --- | --- | --- |
| **token 层** | **本节 §4.4 / §4.5 / §4.6 / §4.7** | 色板取值、字体、度量、控件外观 |
| **布局层** | **`design/mockup.html`** | 窗口外壳结构（`.win` / `.titlebar` / `.body` / `.side` / `.main`）、应用顶栏的内容与顺序（logo · 品牌 · 版本号 · 状态 pill）、页面骨架（`h1` + `.sub` + `.card`）、列表行内部结构 |

**实现任何页面前必须对照 `design/mockup.html` 的对应 section。** 只读本节的 token 与 §2 的信息架构**不足以**还原布局：品牌放在顶栏还是侧栏、顶栏里有没有版本号、页面骨架长什么样、侧栏的内边距与分组方式——这些只写在设计稿里。

**两处不一致时**：token 以本节为准，布局以设计稿为准；若判定其中一处确实写错，按 [12 §7](12-CONVENTIONS.md) 改**那一处**，**不得**在两处各写一半（这正是本节开头"一处事实，一处定义"的要求）。

### 4.3 主题模式

| 项 | 规定 | 契约 |
| --- | --- | --- |
| 主题集合 | 浅色、深色 | — |
| 首次默认 | **浅色** | B-804 |
| 持久化 | 切换后写入 `settings.theme`；升级不重置 | B-804 |
| 启动读取 | 首次渲染必须直接使用持久值，**不得**先渲染默认色再切换 | B-803 |
| 切换一致性 | 全部依赖主题的元素同步更新，无旧主题残留 | B-805 |
| 高 DPI | 缩放与高 DPI 下视觉一致 | B-802 |

**实现要求**：主题必须在**首帧前**确定（由绑定层注入初始值，或内联脚本读取持久值），避免闪烁。

### 4.5 字体

```css
/* 正文 */
font-family: "Segoe UI Variable Text","Segoe UI",system-ui,-apple-system,"Microsoft YaHei",sans-serif;
/* 等宽：路径、错误码、指纹 */
font-family: "Cascadia Mono",Consolas,ui-monospace,monospace;
```

| 项 | 规定 |
| --- | --- |
| 基准字号 | **14px**，行高 1.55 |
| 页面标题 `h1` | 19px / 650 |
| 区块与强调 | 600（卡片标题、主按钮） |
| 元信息 | 12.5px（次）/ 12px（三级） |
| 徽标文字 | 11.5px / 600 |
| 等宽 | 12px |
| 字距 | 只在 `h1` 用 `+0.2px`，其余默认 |

**不引入任何需要打包的第三方字体**——字体文件会增大安装包，且与「装完即用」的定位冲突。

| 卡片 / 弹窗圆角 | **12px** |
| 控件圆角（按钮/输入/下拉/小按钮） | 7px |
| 侧栏圆角（导航项） | 8px |
| 缩略图圆角 | 6px |
| 徽标 / pill / 开关 / 进度条 | 全圆角 |
| 侧栏宽度 | **196px** |
| 标题栏高度 | **48px** |
| 导航项内边距 | 9px 12px |
| 卡片行内边距 | 15px 17px |
| 字段行内边距 | 14px 17px（标签列宽 132px） |
| 主区留白 | 22px 26px 30px |
| 进度条高度 | 6px |
| 开关 | 40×22px，滑块 16px |
| 间距 | 4 的倍数；同行元素 8 / 10，区块间 14 / 18 |
| 卡片阴影 | `0 1px 2px rgba(16,24,40,.05), 0 6px 16px rgba(16,24,40,.055)` |
| 弹窗阴影 | `0 16px 48px rgba(16,24,40,.22)` |

### 4.7 控件

| 控件 | 规定 |
| --- | --- |
| 主按钮 | 强调色填充 + 白字 + 600 字重；hover 提亮 6% |
| 次按钮 | 主表面 + 1px 描边；hover 变次级表面且描边转三级文字色 |
| 危险按钮 | 红字 + 30% 透明红描边（**不用红色填充**，避免误触） |
| 禁用 | 透明度 .45，光标 `not-allowed` |
| 分段控件 | 描边容器 + 选中段用强调色填充、白字 600 |
| 开关 | 关闭为轨道色，**开启为强调色**；滑块白色带阴影 |
| 输入框 / 下拉 | 次级表面底 + 1px 描边；focus 时描边转强调色并加 3px 强调色浅底光晕 |
| 徽标 | 全圆角，字 11.5px / 600，底色为语义色的 10–12% 透明 |
| 侧栏导航项 | 默认次级文字色；hover 主表面 + 主文字色 + 极轻阴影；**选中为强调色浅底 + 强调色文字 + 600，并在左侧加 3px 强调色竖条** |
| 列表行 | hover 次级表面；**选中为强调色浅底**；不使用整行反白 |
| 页面标题 | `h1` 下方加一条 28×3px 强调色短横线——给页面一个视觉起点 |
| 统计卡 | 主表面 + 左侧 3px 色条（进行中=强调色 · 已完成=成功 · 失败=危险 · 其他=中性描边） |
| 提示条 | 主表面 + 1px 描边 + **左侧 3px 强调色条**，用于解释性说明；**不得**用整块彩色底 |
| **图标** | 一律用**内联 SVG**（`currentColor` 描边，16px 视框）；**禁止**用字体字符拼图形——圆形边框加字母之类的写法依赖字体基线，换字体或改缩放就会错位。ⓘ 提示图标为 15px |
| 图标配色 | 默认三级文字色；hover 与键盘 focus 转强调色。不填色块，只描边 |
| **详细说明的呈现** | 用**自定义 tooltip**（深底白字、宽 262px、自动换行、`position:fixed` 定位）。**禁止**用原生 `title` 承载正文说明——它在窄容器（扩展弹窗）里会被裁切、延迟长、样式不可控 |
| tooltip 行为 | 悬停与键盘 focus 都触发；自动判断显示在图标上方或下方并夹在视口内；箭头对准图标；`Esc` 或滚动时关闭 |

### 4.8 扩展弹窗

弹窗**与桌面端共用 §4.4 ~ §4.7 的全部 token**，但保留浏览器弹窗的原生约束（宽度上限、无自定义标题栏）。

**结构**：标题栏（图标 + 名称 + 连接状态）· **标签页** · 内容区（滚动）· 底部操作栏（固定）。

**标签页**（候选与任务必须**分开**，不得挤在同一屏）：

| 标签 | 内容 | 底部操作栏 |
| --- | --- | --- |
| **候选** | 候选列表（缩略图、清晰度、音轨、预计输出） | 下载到电脑 / 下载到 Eagle |
| **任务** | 任务列表（标题、进度条、进度数值、状态徽标） | 打开下载文件夹 / 刷新 |
| **设置** | 见下表 | 无（设置项即时生效） |

标签上的数字角标表示该类的**活动条目数**（候选数 / 进行中任务数）；无内容时不显示角标。

**设置页的呈现规范**——**必须按标准设置项写，不得写成说明文**：

| 项 | 规定 |
| --- | --- |
| 布局 | 一行一项：左侧为「名称 + 一句说明」，右侧为该设置的控件 |
| 名称 | 13px / 600 |
| 说明 | **只允许一行**，11.5px / 三级文字色。禁止段落式说明 |
| 详细解释 | 收进名称后的 ⓘ 图标（悬停显示完整说明），**不占用页面空间** |
| 分组 | 用 `sect` 小节标题分组：下载 / 连接 / 诊断 |
| 禁止 | 大段说明文字、整块彩色提示框、把"为什么"写在界面上 |

**设置页的内容**：

| 分组 | 项 | 控件 |
| --- | --- | --- |
| 下载 | **浏览器下载模式** | 开关（唯一存在位置，B-220）+ ⓘ 说明 |
| 连接 | 桌面端 | 地址与连接状态 pill |
| 连接 | 版本 | 扩展版本 · 适配器数量 |
| 诊断 | 诊断信息 | 导出按钮 |

**设置页的禁止内容**：媒体 URL、解密信息、Cookie、签名参数（B-722、B-223）。

## 6. 性能要求

这是重写的核心目标之一。

| # | 要求 |
| --- | --- |
| PF-1 | **前端不轮询**，状态由事件推送驱动。唯一例外是 [04 §4.4](04-INTERFACES.md) 的启动与重连对齐（直接拉一次列表）。**扩展侧不受此条约束**——它有自己受限的轻量轮询（[07 P-108](07-EXTENSION.md)） |
| PF-2 | 列表虚拟滚动，DOM 节点数有上界 |
| PF-3 | 单条更新不触发整列表重渲染 |
| PF-4 | 绑定方法调用不得阻塞渲染 16 ms 以上 |
| PF-5 | 图片（封面、预览）有尺寸上限与懒加载 |
| PF-6 | 切换页面不重建整棵应用树 |
| PF-7 | 空载时不存在定时器忙循环 |
| PF-8 | 终态更新立即渲染，不被节流吞掉（[04 §4.2](04-INTERFACES.md) 终态规则） |
