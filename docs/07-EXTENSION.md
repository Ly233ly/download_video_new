# 07 · 浏览器扩展

本文定义扩展的处置策略、必须固化的行为，以及相对新桌面端的适配。

**旧实现基线**：`chrome-extension/`，28 个文件、7,789 行 JS。

---

## 1. 处置策略：复用

扩展是**纯 JavaScript + Manifest V3**，与桌面端语言无关。重写**不改变扩展的实现语言与用户可见行为**，只做接口适配。

| 项 | 处置 |
| --- | --- |
| 扩展源码 | **复用**，迁入新仓库 `extension/` |
| 用户可见行为 | **不变**（B-2xx 全部继续成立） |
| 与桌面端通信 | **适配**：Origin 白名单下的端点调用 |
| 站点专用脚本 | **迁移**到 `adapters/<site>/`，见 [14](14-SITE-ADAPTERS.md) |
| 构建方式 | 保持"源码即产物"，无打包器 |

**扩展 ID 必须稳定**：manifest 中固定 `key` 字段，使 ID 在开发者模式与打包后保持一致。桌面端以编译常量内置该 ID 作为 Origin 白名单（见 [01 §2.1](01-ARCHITECTURE.md)）。这是"装完即用、无需配对"的技术前提。

**理由**：扩展不受旧实现的三个性能根因影响，且它的复杂度集中在**时序与竞态**——这类逻辑重写极易重新引入已修复的缺陷。19 条契约与 7 个测试文件是已投入的资产。

## 2. 文件结构

| 文件 | 职责 |
| --- | --- |
| `manifest.json` / `manifest.firefox.json` | 清单 |
| `js/background.js` | Service Worker：导航边界、代次、发现、任务轮询 |
| `js/content-script.js` | 页面内发现与上报 |
| `js/eagle-bridge-candidate-logic.js` | 候选组归组与选择 |
| `js/eagle-bridge-ui.js` / `-ui-logic.js` | 弹窗界面 |
| `js/eagle-bridge-auth-logic.js` | 连接状态机（**简化后只判断可达性**） |
| `js/eagle-bridge.js` | 与桌面端通信 |
| `catch-script/` | **已取消**。站点专用脚本迁往 `adapters/<site>/extension.js`（[14](14-SITE-ADAPTERS.md)） |
| `site-adapters.json` | **构建生成**的站点适配器副本（来源 `adapters/`，禁止手工编辑） |
| `css/` · `popup.html` | 样式与入口 |

**站点专用逻辑不在扩展包内维护**：注入脚本与站点判定一律放 `adapters/<site>/`，构建时抽取。扩展源码里**禁止**出现站点名判断。

## 3. Service Worker 生命周期

MV3 Worker 会被浏览器强制终止，扩展必须自行保活并在冷启动后恢复状态。

| 要求 | 规定 |
| --- | --- |
| 保活 | 维持心跳 Port 与周期性活动 |
| 冷启动 | 必须**先恢复设置与媒体快照**，再处理候选（B-209） |
| 状态存储 | 跨 Worker 生命周期的**非敏感**状态放 `chrome.storage.session`（内存）；确需持久化的放 `local` |
| 内存态禁止假设 | 任何变量都可能在任意时刻丢失，不得作为权威状态 |

**存储区域选择**：

| 数据 | 区域 | 理由 |
| --- | --- | --- |
| 候选快照 | `session` | 扩展级内存，**不随单个标签关闭自动清除**；必须在关标签或清空候选时主动移除 |
| 站点开关的本地副本 | `local` | 需要持久 |
| 浏览器下载模式的本地缓存 | `session` | **只作显示缓存，权威在桌面端**（B-220）；弹窗打开时重新读取 |
| 未完成的中转上传任务 | `session` | Worker 被回收后据此恢复上传；**只存进度与偏移，不存媒体地址与字节**（B-223） |
| 连接状态 | `session` | 可重建 |
| 桌面端地址与能力 | `session` | 可重建 |

**不得**把 Cookie、Authorization 或签名 URL 写入任何 storage 区域。

## 4. 代次模型

用 `captureGenerationByTab` 使在途异步发现失效。

**契约**：用户清空标签候选时，已发出的异步发现结果**不得**把刚被清掉的条目重新追加回来（B-215）。

1. 每个标签维护单调递增代次。
2. 异步发现开始时记录当前代次。
3. 回调提交前比对；不一致则**丢弃结果**。
4. 清空候选、导航、标签关闭都必须递增代次。

同样的模式适用于**任务轮询、健康探测、站点状态**三类异步请求（B-215、B-216）。

## 5. 导航边界模型

| 事件 | 性质 | 处置 |
| --- | --- | --- |
| `onBeforeNavigate`（顶层） | 文档边界开始 | 清空该标签的第一方请求上下文；按暂存规则处理候选清理 |
| `onCommitted`（顶层） | 文档边界确立 | 按用户自动清理设置清空旧候选 |
| `onHistoryStateUpdated` / `onReferenceFragmentUpdated` | 仅位置变化 | 只重置发现上下文，**继续累积**候选（B-207） |

**核心区别**：单页应用换视频 ≠ 换文档。只有完整文档导航才允许清空候选。

### 5.1 冷启动暂存

Worker 可能在设置与媒体快照尚未恢复时先收到导航事件。此时：

1. 把边界（`loading` / `committed`）**暂存**。
2. 在以下时点前**必须冲洗**：接收第一个新候选之前、弹窗读取权威快照之前。
3. 冲洗后，旧候选清理必须**先于**新文档媒体入库完成（B-208）。

### 5.2 清理时机

| 模式 | 触发点 |
| --- | --- |
| 高频模式 | 顶层 `onBeforeNavigate` **同步**执行 |
| 默认模式 | 顶层 `onCommitted` **同步**执行 |

**禁止**把完整文档清理排进异步闹钟——会引入迟到删除（B-208）。

## 6. 候选组模型

| 要求 | 契约 |
| --- | --- |
| 归组 | 同一内容的画面、音轨、不同质量归入**一个**候选组（B-201） |
| 必显信息 | 标题、预览、类型、清晰度、音轨、预计输出（B-202） |
| 技术 URL | 只能作为**展开后**的信息（B-203） |
| 默认隐藏 | 固定字节分片、预加载资源、无法归属的请求（B-205） |
| 滚动位置 | 切换质量、点击底部候选、批量选择**不得**回滚到顶部（B-206） |
| 更新粒度 | 只原位更新行状态，集合真正变化才重绘并保留滚动（B-219） |

### 6.1 有界资源

一切对候选有影响的远程资源读取（清单、目录、探测响应）都必须有**字节上限与超时**，超限必须取消而非截断使用。

| 项 | 值 |
| --- | --- |
| 单次资源读取字节上限 | **2 MB**（沿用旧实现实测值） |
| 单次资源读取超时 | **10 s** |

截断使用是错的：截断后的清单会被当成完整清单解析，产出错误候选——宁可取消并提示。

### 6.2 列表渲染性能

**这是重写必须解决的首要问题。** 旧扩展的列表卡顿有明确实测根因（`js/eagle-bridge-ui.js`，1,598 行 / 107 KB）：

| 证据 | 实测值 |
| --- | --- |
| 整体 `innerHTML` 字符串重建 | **9 处** |
| `createElement` / `appendChild` | **0 次**——完全没有增量更新 |
| 任务轮询间隔（有活动任务时） | **1.2 秒**一轮 → `refreshPlans()` → `renderTasks()` 全量重建 |
| 弹窗打开时的并发请求 | **6 个**（含全量候选 + 全量预览图） |
| 预览图载体 | base64 data URL 常驻内存 |
| 行事件 | 逐行挂监听，每次重绘即重挂 |

**结论**：卡顿不是数据量问题，是**每次更新都重建整个 DOM**。候选只有几十条也会卡。

契约（`P-1xx`）：

| # | 契约 | 要求 |
| --- | --- | --- |
| P-101 | 集合不变不重绘 | 只有候选**集合**真正变化才允许增删行；状态变化只改该行文本与属性 |
| P-102 | 禁止整体重建 | **禁止**对列表容器或其祖先赋 `innerHTML` |
| P-103 | 节点复用 | 以稳定 ID（候选组 ID）建立节点索引并复用；**禁止**逐行 `createElement` 重建 |
| P-104 | 事件委托 | 监听只挂在列表容器上，行内不挂监听 |
| P-105 | 虚拟滚动 | 行数超过 **50** 时只渲染可见窗口与上下缓冲。**参数必须是固定值**：行高 **56px**、可见 **12 行**、上方缓冲 **3** 行、下方缓冲 **5** 行。只有固定行高才算得出起始索引——不得改成测量式（§10 `E6` 已因此关闭） |
| P-106 | 帧预算 | 同一帧内的多次更新必须合并，每帧最多渲染一次；超出预算时切片处理 |
| P-107 | 缩略图用 URL | 缩略图必须用**图片 URL** 交给浏览器缓存；**禁止**以 base64 常驻内存，**禁止**为列表项逐条截图。无可用图片时用占位图。**加载时机**：只对**可视区内的行**赋 `src`；滚动停止后再补相邻行；图片请求并发上限 **4** |
| P-108 | 轮询受限 | **禁止**常驻轮询与全量数据轮询。任务列表在弹窗打开期间可用不低于 **2 秒**的轻量轮询，弹窗关闭立即停止（与 §7 AD-7 一致） |
| P-109 | 关闭即停 | 弹窗关闭后不得有任何渲染或定时任务残留。**例外**：中转上传循环（§6.3）必须继续到该文件传完 |
| P-110 | 上传不阻塞渲染 | 浏览器下载模式的上传循环必须与列表渲染解耦：上传分片**不得**进入渲染帧预算，进度只按节流更新该行文本 |

**B-219 与 P-101 的关系**：B-219 要求"只原位更新行状态"，P-101/P-102 把它变成可检查的约束——**出现一次整体重建即视为违反**。

### 6.3 浏览器下载模式

**开关只在弹窗内**（B-220），默认关闭。开启时的链路：

```text
弹窗内切换开关
  → POST /api/mode                    写入桌面端（唯一权威）
  → 用户点下载
  → 扩展 fetch(媒体地址, { credentials: 'include' })    ← 浏览器自己的会话
  → PUT    /api/upload                声明 track 与 declaredBytes，取回已接收偏移
  → POST   /api/upload?offset=...     顺序分片（裸字节）
  → DELETE /api/upload  complete      结束并交给桌面端合并、校验、落盘
```

| 要求 | 规定 |
| --- | --- |
| 开关位置 | **只在弹窗的「设置」标签页内**；桌面端设置页不设（B-220、[09 §4.8](09-UI.md)） |
| 状态权威 | 桌面端 `settings.browser_download_mode`；扩展本地只在弹窗打开期间缓存，**不作为权威** |
| 预检 | `PUT` 前按 [03 §4.6](03-DATA.md) 上限检查 `declaredBytes`；超限**不发字节**，直接提示改用软件下载（B-224） |
| 续传 | 必须使用 `PUT` 返回的 `received` 作为首个分片偏移（B-225） |
| 生命周期 | 上传循环绑定**该次下载**而非弹窗；弹窗关闭、切标签、Worker 被回收后必须能恢复（B-222） |
| 失败恢复 | Worker 冷启动后从 `storage.session` 恢复未完成的上传任务并继续 |
| Worker 回收风险 | 长时间大文件上传期间必须主动保活；无法保活时如实提示「请保持浏览器打开」 |
| 地址保密 | 媒体地址只驻留内存，**不得**上传给桌面端做展示以外的用途，**不得**写入 storage（B-223） |
| 视频号 | 此模式下视频号入口**不走**中转，保持原捕获逻辑并提示（B-226） |
| 不得改的 | 候选发现、归组、导航边界、代次（§4、§5、§6.1）**不受**本模式影响 |

## 7. 相对新桌面端的适配

这是本文中**唯一需要改动扩展**的部分。

| # | 适配项 | 说明 |
| --- | --- | --- |
| AD-1 | 认证 | **删除配对码与令牌逻辑**，改为直接调用（桌面端按 Origin 放行） |
| AD-2 | 连接流程 | 找不到桌面端 → 显示启动引导；不再有"恢复令牌"概念 |
| AD-3 | 端点路径 | 按 [04 §2.3](04-INTERFACES.md) 同步 |
| AD-4 | 能力字段 | 健康接口返回的字段 |
| AD-5 | 端口发现 | 桌面端换备用端口时的发现机制（B-214） |
| AD-6 | 清单版本号 | 随产品版本同步（B-104） |
| AD-7 | 任务列表接口 | 仅任务状态、不低于 **2 秒**、弹窗关闭即停的轻量轮询（P-108）；桌面端将来若提供推送，可替换 |
| AD-8 | 浏览器下载模式 | **新增**：弹窗内开关（`/api/mode`）与中转上传（`/api/upload`），见 §6.3。这是本次唯一**新增功能**的适配项，不是既有逻辑的改写 |
| AD-9 | 视觉 | 弹窗与桌面端共用同一套设计 token（[09 §4](09-UI.md)），但**保留浏览器弹窗的原生约束**（宽度上限、无自定义标题栏） |

**约束：§4、§5、§6 是冻结区。** 适配改动**不得**触碰它们承载的任何逻辑——三类导航事件的处置差异、冷启动暂存与冲洗顺序、代次失效语义、候选组归组规则、滚动位置保持（B-206）、默认隐藏技术资源（B-205）、Eagle 不可用时的按钮降级（B-211）。这些是回归高风险区，由 §4/§5/§6 的正文与 B-201 ~ B-219 定义，已有 7 个测试文件覆盖。

> 本节不再单列"不得改变的部分"清单：那与上面这句是同一约束，且 7 条内容各自已在对应章节定义（设计原则 3：一处事实，一处定义）。
