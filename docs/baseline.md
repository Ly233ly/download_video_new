## 2. 已测项

### 2.1 `B-1` 冷启动到可交互（→ 对应 `PF-A4`）

**口径**：从进程创建到主窗口出现**且响应 Windows 消息**（`WM_NULL` + `SMTO_ABORTIFHUNG`）。统计完整进程树。

| 目标 | n | min | **p50** | p95 | max | 进程树 | 工作集 | 句柄 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| **冻结 1.6.3 后端**（权威基准） | 7 | 1026.7 ms | **1060.6 ms** | 1187.3 ms | 1283.8 ms | 1 | ~62 MB | ~465 |
| **完整用户路径**（含 C# 启动器） | 5 | 1122.8 ms | **1136.3 ms** | 1238.2 ms | 1390.4 ms | 2 | ~90 MB | ~746 |
| 源码版 1.6.3（对照，非发行形态） | 5 | 1043.1 ms | 1082.5 ms | 1102.5 ms | 1177.7 ms | 1 | ~59 MB | ~364 |

**读法**：启动器（`留底下载器.exe`，C# 托盘宿主）带来约 **+76 ms** 与 **+28 MB / +281 句柄**。用户实际双击的是启动器，所以 `PF-A4` 应代入**完整用户路径的 p50 = 1136.3 ms**。

**代入值**：

| 判据 | 公式 | 代入后 |
| --- | --- | --- |
| [11 `PF-A4`](11-ACCEPTANCE.md) | p50 ≤ `min(8 s, 基线 × 1.0)` | **p50 ≤ 1136.3 ms** |
| | p95 ≤ `min(10 s, 基线 × 1.2)` | **p95 ≤ 1363.6 ms** |

> 说明：8 s / 10 s 的绝对上限远未逼近，所以这一项实质上就是"不比旧版慢"。

### 2.2 `B-2` 空闲常驻 CPU / 内存 / 句柄（→ 对应 `PF-A3`）

**口径**：冻结后端启动后静置 30 s 进入稳定态，再以 **10 s** 间隔采样，每样本按 `ΔCPU秒 / Δt` 计算占用百分比。完整进程树（该场景下为单进程）。

| 指标 | 值 |
| --- | --- |
| 样本数 | 12 / 12 有效（无一丢失，`LostAtSample = -1`） |
| 采样时长 | 2 分钟（**未达 [11 §3](11-ACCEPTANCE.md) 要求的 ≥ 10 分钟**，见 §3） |
| CPU 均值 | **0.06 %** |
| CPU 最大 | 0.148 % |
| CPU p95 | 0.148 % |
| 工作集 首 / 末 | 64.26 MB → 64.16 MB |
| 工作集 min / max | 64.16 / 64.26 MB |
| 工作集增长 | **−0.10 MB**（完全平稳） |
| 句柄 首 / 末 | 456 → 444（增长 −12） |

**代入值**：

| 判据 | 公式 | 代入后 |
| --- | --- | --- |
| [11 `PF-A3`](11-ACCEPTANCE.md) CPU | ≤ 1 %（硬上限） | 旧版 0.06 % → **新实现仍按 1 % 硬上限判**，此值仅作对照 |
| [11 `PF-A3`](11-ACCEPTANCE.md) 内存 | ≤ `max(200 MB, 基线 × 0.8)` | **≤ max(200 MB, 51.3 MB) = 200 MB**（基线取 64.16 MB × 0.8） |
| [11 `PF-A3`](11-ACCEPTANCE.md) 句柄 | ≤ `max(1500, 基线 × 1.0)` | **≤ 1500**（基线 444 < 1500，硬上限生效） |

### 2.3 顺带得到的两项事实

| 事实 | 值 | 出处 |
| --- | --- | --- |
| 空闲线程数 | 25（冻结） / 13–27（源码） | 原始样本 `Threads` 字段 |
| **测量期间系统代理未被改动** | 全部 17 次启动 `ProxyChanged = false` | 原始样本 `Proxy*` 字段 |

> 第二项有独立价值：旧版在**未开始捕获**时不会碰系统代理，这与 [01 §6](01-ARCHITECTURE.md) 的"只在捕获时才改代理"一致。测量全程用户的 FlClash 代理（`127.0.0.1:7890`）保持可用。

## 3. 未测项（**必须显式标注，不得留空**）

[13 §3.2](13-ROADMAP.md) 要求 `B-1` ~ `B-8` 全覆盖，以下是缺口与原因：

| 项 | 状态 | 原因 | 影响的判据 |
| --- | --- | --- | --- |
| `B-3` 1000 条任务列表滚动帧率分布 | **未测** | Tkinter 无"帧率"概念，旧版也没有帧回调；需要另行定义等价量（滚轮分发耗时 + 重绘次数）。脚手架 `measurement/Measure-UI.ps1` 已就绪但未跑 | `PF-A1` |
| `B-4` 1000 条下单条状态更新耗时与 DOM 变更数 | **未测** | 同上；旧版是 `innerHTML` 全量重建模型，没有"单条更新"这个操作可比 | `PF-A2`、`T-UI-06` |
| `B-5` 捕获开启时的吞吐 / CPU / 额外延迟 | **未测** | 需要真实微信视频号流量，属人工复验边界（[11 §5](11-ACCEPTANCE.md) M3） | `PF-A5` |
| `B-6` 并发 3 下载时界面响应 | **未测** | 需要真实下载任务与受控带宽 | `PF-A6` |
| `B-7` 扩展候选 200 条滚动与更新 | **未测** | 旧扩展是浏览器内运行，需 Chrome 实例与人工操作（[11 §5](11-ACCEPTANCE.md) M1/M13） | `PF-A7` |
| `B-8` 连续运行 1 小时内存增长 | **未测** | 本次只采到 2 分钟稳定段（增长 −0.10 MB）。1 小时观察窗口未执行 | `ST-7` 的对照参考 |

**另外两处口径缺口**（不影响判据代入，但必须记住）：

1. **空闲采样时长不足**：2 分钟 < [11 §3](11-ACCEPTANCE.md) 要求的 **≥ 10 分钟**稳定态。已采数据内部一致（12/12 有效、增长为负），但严格说不满足口径。
2. **`tracemalloc` 不是工作集**：旧项目的 `tests/visual_ui_fixture.py` 输出的内存字段来自 `tracemalloc`，只测 **Python 堆**，**不能**当作进程工作集使用。本文的内存数字全部来自外部进程树采样，与该 fixture 无关。

## 4. 测量方法与可复现性

| 项 | 做法 |
| --- | --- |
| 被测构建 | 用官方安装器的 `--test-install` + `IDM_EAGLE_INSTALL_ROOT` **隔离解包**到 `measurement/old-1.6.3`，后端 SHA-256 与官方验证页逐字节一致 |
| 不污染用户环境 | 数据目录经 `IDM_EAGLE_DATA_DIR` 指向一次性目录；**未触碰**用户已安装的 1.6.1 实例与其数据 |
| 进程定位 | **按可执行文件路径**匹配，不按父子关系——`--external-tray` 下真实后端是孤儿进程（父引导进程 re-exec 后退出），树遍历找不到它 |
| 冷启动判定 | 主窗口可见**且**响应 `WM_NULL`（带 `SMTO_ABORTIFHUNG`），两者都满足才记时 |
| 单实例干扰 | 旧版用命名互斥体 `Local_IdmEagleAutoImport` 保证单实例。**残留实例会让后续每次启动立刻退出**，所以每轮测量前先杀掉残留并断言互斥体空闲 |
| 超时 | 每次启动 ≤ 120 s；未在窗口期出现记为无效样本（本次无此情况） |

### 4.1 测量过程中发现的两个旧版行为（对重写有参考价值）

| 发现 | 事实 | 对重写的意义 |
| --- | --- | --- |
| 引导进程 re-exec | 冻结版启动时第一个进程会 re-exec 并退出，真正长期存活的是它的子进程；该子进程父进程已消失，成为孤儿 | [01 §4](01-ARCHITECTURE.md) 的"捕获子进程由父进程持有等待句柄"设计**不能假设父进程永远在**；单实例与恢复责任要按"可能成为孤儿"来设计 |
| 冷启动首轮偏慢 | 第 1 次运行 1087 ms（还带一个 `留底下载器` 标题的额外窗口），后续 5 次稳定在 1026–1187 ms | 冷启动测量必须**丢弃首轮**，否则样本被初始化开销污染 |

## 5. 复现命令

```powershell
# 冷启动（权威：完整用户路径）
powershell -NoProfile -ExecutionPolicy Bypass -File measurement\Measure-ColdStart.ps1 -Target launcher -Count 5

# 冷启动（后端本体，用于分解启动器开销）
powershell -NoProfile -ExecutionPolicy Bypass -File measurement\Measure-ColdStart.ps1 -Target frozen -Count 7

# 空闲常驻（Minutes 建议 ≥ 10 以满足 docs/11 §3 口径）
powershell -NoProfile -ExecutionPolicy Bypass -File measurement\Measure-Idle.ps1 -Minutes 10

# UI 计时（复用旧项目自带的 fixture；只取时间字段，内存字段是 tracemalloc 不可当工作集）
powershell -NoProfile -ExecutionPolicy Bypass -File measurement\Measure-UI.ps1 -Scenario stress -Iterations 20
```
