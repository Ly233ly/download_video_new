# ADR-001 · 采用全量重写

- **状态**：已接受
- **相关**：[README](../../README.md)、[01 架构](../01-ARCHITECTURE.md)

## 背景

现有实现由 Python 运行时、Tkinter 界面（8,570 行手绘控件）、C# 启动器与安装器、浏览器扩展组成。存在三个结构性性能根因：

- **A** — Tk 主线程叠加多个 90–250 ms 轮询定时器
- **B** — 纯 Python 手写 TLS 中间人代理
- **C** — 无统一调度的裸线程模型

> **证据说明**：以上来自**代码层面**观察（定时器数量、代理实现方式、线程创建点）。阶段 0.5 会补测旧版本的真实 CPU/内存/延迟基线。在基线出来之前，上述是**风险判断**而非已证实的性能因果。

## 决策

**全量重写**，业务逻辑一并重写；不保留 Python/Tk/C# 运行时，不建兼容层。

## 理由

三个根因分别位于 UI 层、网络层与并发层。任何局部改造只能消除其中一个，而逐层替换的总成本不低于一次重写，却要长期维护两套技术栈的接缝。

## 后果

**正面**：三个根因可同时消除；技术栈收敛；借机清理历史遗留。

**负面**：需重新实现全部业务规则，回归风险高；依赖行为契约的完整性；旧测试无法直接复用，只能作为行为对照。

## 替代方案

| 方案 | 否决理由 |
| --- | --- |
| 只换 UI 层 | 仅消除根因 A |
| 只换捕获代理 | 仅消除根因 B |
| Python + PySide6 | UI 改善但代理与 GIL 问题依旧 |
| 保留 Python 内核 + Go 代理 | 长期维护两套技术栈接缝 |
