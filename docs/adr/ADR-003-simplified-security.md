# ADR-003 · 安全模型简化为「防自己出错」

- **状态**：已接受
- **相关**：[README](../../README.md) 设计原则 2、[02 附录](../02-BEHAVIOR.md)、[03 §4](../03-DATA.md)、[04 §2](../04-INTERFACES.md)

## 背景

重写的第一版文档把「本机个人工具」当作「多租户服务」设计：三重认证（Origin + 配对 + 令牌）、bootstrap 一次性秘密、令牌摘要存储与轮换、11 项威胁模型、租约归属判定算法、SSRF 每跳校验。

这些机制防的是"同机恶意进程伪造 HTTP 头"。但它们引入了大量复杂度，其中的自相矛盾又需要额外工作去修——**独立审查把其中相当一部分列为了最高优先级风险**。

同时，产品定位是：**无登录、无账号、无配对，安装即可用**。三重认证与这个定位直接冲突。

## 决策

安全模型收敛为一句话：**对手不是攻击者，是程序自己的 bug。**

| 要做 | 不做 |
| --- | --- |
| 不误删用户文件 | 防同机恶意进程 |
| 崩溃后不断网 | 防伪造 Origin 头 |
| 不损坏数据库 | 防时序攻击 |
| 不静默降级画质 | 防侧信道 |
| 路径穿越 / 命令注入 | 配对认证、令牌轮换 |

保留的校验全部是**输入合法性校验**：URL 协议与主机（拒绝本机/内网目标）、路径穿越、Windows 保留名、字符串与请求体长度上限、状态枚举。

## 具体简化

**这是本决策的权威记录**——[01 §9](../01-ARCHITECTURE.md) 的禁止事项 `N12` 引用本表作为"已删除机制"的依据，正文不再重复。

| 项 | 简化前 | 现在 |
| --- | --- | --- |
| 认证 | Origin + 配对 + 令牌 | **仅 Origin 白名单** |
| 进程通信 | 回环 HTTP + 令牌 | **管道 JSON-RPC**（父子关系即身份） |
| 代理恢复 | 租约文件 + 归属判定算法 | **original/applied 值比对** |
| bridge 上报 | 回环 HTTP（网页能否访问内部接口存疑） | **代理拦截同源路径** |
| SSRF | 每跳、子清单、重定向全查 | **只查提交的那一条 URL 的主机** |
| 威胁模型 | 11 项 | 删除，改为"防自己出错"清单 |

## 后果

**正面**：删掉约 1/3 的安全相关契约与实现；消除由安全设计引发的自相矛盾；与"安装即用"的产品定位一致。

**负面（必须承认）**：

- 本机任何程序都能调用下载 API。它能做的：创建下载任务、读任务列表。它**不能**读用户文件、不能删用户的东西。
- 恶意网页理论上能尝试，但 Origin 白名单挡住。

**接受这个代价的理由**：如果一台机器上已存在能伪造 HTTP 头的恶意程序，用户的下载记录不是最要紧的问题。为这个场景付出的开发成本，远高于它带来的保护。

## 何时重新评估

| 触发条件 | 说明 |
| --- | --- |
| 引入多用户或远程访问 | 威胁模型根本改变 |
| 需要保护下载历史本身 | 例如加入账号同步 |
| 出现真实的本机攻击案例 | 从实际威胁出发重新设计 |

变更此决策必须新增 ADR。

## 替代方案

| 方案 | 否决理由 |
| --- | --- |
| 保留三重认证 | 与"无登录、装完就用"定位冲突，且引发大量自相矛盾 |
| Origin 白名单 + 静态 token | 成本小但仍需处理令牌分发与失效；当前无实际威胁对应 |
| 完全不做 Origin 校验 | 网页可跨源调用，属真实 bug 风险，保留白名单成本几乎为零 |
