## 1. 验证层次

| 类型 | 标记 | 含义 |
| --- | --- | --- |
| 自动化 | **A** | 可在 CI 或本地脚本中完全自动判定 |
| 人工 | **M** | 必须由人在真实环境中确认 |
| 混合 | **A+M** | 自动测试覆盖规则，人工确认真机效果 |

## 3. 性能验收

必须与旧版本做**同场景对比**。判据写法分三类，**每项都必须能机械判定**：

| 类 | 含义 | 判定时点 |
| --- | --- | --- |
| **硬数值** | 阈值是绝对数，已在本套文档中有依据 | 立即可判 |
| **相对判据** | 阈值写成 `基线 × K`，K 已定、基线在阶段 0.5 代入 | 阶段 0.5 后 |
| **流程判据** | 判"证据是否齐备且可复现"，不判快慢 | 立即可判 |

| 编号 | 场景 | 判据 |
| --- | --- | --- |
| PF-A1 | 1000 条任务列表滚动 | **相对 + 硬下限**，阈值 = `max(50 FPS, 基线 × 1.5)`：滚动全程 p95 帧率 ≥ 阈值，且 p99 帧时间 ≤ **33 ms**；单次滚动期间长任务（> 50 ms）数量 ≤ **2**。统计口径：从滚动开始到停止的连续 ≥ **10 s** 区间 |
| PF-A2 | 1000 条任务下状态更新 | **硬数值（与 T-UI-06 同口径）**：单条状态更新的 DOM 变更节点数 ≤ **20**；500 ms 窗口内 DOM 变更总数 ≤ **25**；列表容器**未被整体重建**（布尔）；单次更新触发的主列表查询 ≤ **2** 次 |
| PF-A3 | 空闲常驻 | **相对判据 + 硬下限**：空闲 10 分钟稳定段内 CPU 均值 ≤ **1%**（与 T-STB-05 同口径）；内存（完整进程树工作集）≤ `max(200 MB, 基线 × 0.8)`；句柄数 ≤ `max(1500, 基线 × 1.0)` |
| PF-A4 | 冷启动到可交互 | **相对判据 + 硬上限**：从进程创建到主窗口首帧可交互的 p50 ≤ `min(8 s, 基线 × 1.0)`；p95 ≤ `min(10 s, 基线 × 1.2)`（**阶段 0.5 代入**） |
| PF-A5 | 捕获期间系统吞吐 | **相对判据 + 硬上限**：捕获开启后同一下载场景的吞吐 ≥ `基线 × 0.7`；捕获进程 CPU 占用均值 ≤ **5%**（完整进程树）；额外 p95 网络延迟 ≤ **100 ms** |
| PF-A6 | 并发下载时界面响应 | **相对判据 + 硬上限**：并发 **3** 个下载时，界面交互（切页、滚动、点按钮）到视觉反馈的 p95 ≤ `min(200 ms, 基线 × 1.0)` |
| PF-A7 | 扩展候选列表 200 条滚动与更新 | **相对 + 硬下限**，阈值 = `max(50 FPS, 基线 × 1.5)`：滚动 p95 帧率 ≥ 阈值；状态更新后列表容器**未被整体重建**（布尔，对照 T-EXT-15）；DOM 节点总数 ≤ **60**（按 [07 P-105](07-EXTENSION.md) 固定行高 56px / 可见 12 行 / 缓冲 3+5 行 ⇒ **20 行**，加容器与哨兵仍在上界内） |

**测量口径**：

| 项 | 要求 |
| --- | --- |
| 进程树 | 必须统计完整进程树，含 WebView2、捕获子进程与媒体工具 |
| 内存口径 | 逐进程求和；PF-A3 与 ST-7 按**完整进程树工作集**计 |
| FPS 采样 | 由渲染进程的帧回调统计，逐帧记录而非平均；p95 与 p99 由**原始帧时间序列**排序得出 |
| 指标 | CPU、内存、句柄数、吞吐、延迟 |
| 分位 | 必须给出 p95 / p99，不只平均值 |
| 时长 | 稳定态测量 ≥ 10 分钟 |
| 增长判据 | 统一按 `(末值 − 首值) / 首值` 计算，首值取稳定态起点 |
| 基线代入 | 不确定的阈值一律写"阶段 0.5 代入"并附**空位表格**，禁止留形容词 |
| 样本保留 | ≥ 10 分钟的测量必须保留**逐秒样本**，不得只留汇总量 |
| 记录 | 机器配置、数据规模、对比方法必须写入发布验证文档 |

> **哪些项现在就能判**：PF-A1、PF-A2、PF-A7 有硬下限（基线代入后取 `max`，只会更严）；PF-A3 的 CPU 部分有硬上限。只有 PF-A4、PF-A5、PF-A6 的阈值完全依赖基线。

**基线**：编码前必须先测一次旧版本，作为对比基准（见 [13](13-ROADMAP.md) 阶段 0.5）。基线数值写入 `docs/baseline.md`，本文所有 `基线 × K` 的形式在阶段 0.5 完成后由该文件代入。

## 4. 稳定性验收

| 编号 | 场景 | 判据 |
| --- | --- | --- |
| ST-1 | 强制结束主进程（捕获运行中） | 下次启动恢复代理，网络可用 |
| ST-2 | 强制结束捕获子进程 | **硬数值（引用，不新定）**：主进程在 **3 s** 内完成代理回滚并推送状态事件——该上限见 [01 §5.3](01-ARCHITECTURE.md) 的"代理恢复（含崩溃与兜底路径）**3 s**"；回滚后系统代理四项设置（`ProxyEnable` / `ProxyServer` / `ProxyOverride` / `AutoConfigURL`）与捕获前逐值一致；界面在 **5 s** 内出现可读提示。超限即判失败，不得以"通常很快"替代 |
| ST-3 | 断电模拟（写入中） | 数据库可打开无损坏；在途计划转为可重试 |
| ST-4 | 磁盘满 | 任务失败并给出可读错误，不损坏已有数据 |
| ST-5 | Eagle 反复启停 | 无需重新下载即可补导 |
| ST-6 | 数据库被外部锁定 | **硬数值（引用，不新定）**：外部持锁时，主进程在 `busy_timeout` = **5000 ms**（[03 §5](03-DATA.md)）之后报错返回，**不永久挂起**——判定上限取 **8 s**（5 s 等待 + 3 s 余量，防止把"等不到"误判成"没挂起"）；错误码与提示可读；解锁后无需重启即可继续写入 |
| ST-7 | 连续运行 24 小时 | **流程判据 + 硬上限（不依赖基线）**：稳定态启动后连续运行 **24 h**，① RSS 末值 ≤ 首值 × **1.05**；② 工作集增长 ≤ **50 MB**；③ 句柄数末值 ≤ 首值 + **50**；④ 无单调持续增长（每 1 h 分段的斜率不得 6 段连升）。采样 ≥ **1440** 次（每分钟一次），保留完整样本序列并附增长曲线；超限时必须能定位到具体泄漏点才可判"已解决" |
