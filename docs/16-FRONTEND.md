# 16 · 前端框架规范

本文定义**桌面端前端**（`frontend/`）的框架选型、工程结构、渲染约束与"复用优先"规则。

> **为什么单列一份**：框架选型此前散在 [09 §1](09-UI.md)、[09 §7](09-UI.md) 与 [13 V7](13-ROADMAP.md) 三处，而**渲染约束**（不整列表重建、单条更新只改一行）此前只在扩展侧有契约（[07 `P-101`~`P-110`](07-EXTENSION.md)）。桌面端用 React，那些契约**不会自动成立**——React 默认就会重渲染子树。本文把它变成可检查的框架级约束，并落实"有能复用的就不要重复造轮子"。

---

## 1. 适用范围（先分清两个前端）

本项目有**两个前端**，技术栈不同，**不要混淆**：

| | 桌面端前端 | 浏览器扩展 |
| --- | --- | --- |
| 目录 | `frontend/` | `extension/` |
| 技术栈 | **React 19 + TypeScript + Vite + Tailwind**（本文） | **原生 JS + MV3，无构建步骤**（[07](07-EXTENSION.md)、[12 §1.1](12-CONVENTIONS.md)） |
| 渲染约束 | 本文 §4 | [07 `P-101`~`P-110`](07-EXTENSION.md) |
| 谁定 | 本文 | [07 §6.2](07-EXTENSION.md) |

**两条硬边界**：

1. **扩展不引入 React，也不引入任何构建步骤**（[12 §1.1](12-CONVENTIONS.md) 明确禁止）。`P-101`~`P-110` 是手写 DOM 的契约，**不能**指望 React 满足它们——扩展侧只能靠 §6.2 的写法。
2. **桌面端前端不得直接进行文件系统、进程、注册表或网络操作**（[09 §1](09-UI.md)）。一切数据只经 [04 §3/§4](04-INTERFACES.md) 的绑定方法与事件。

## 2. 选型（已定，不再比较）

| 层 | 选型 | 版本口径 | 理由 |
| --- | --- | --- | --- |
| 框架 | **React 19** | 主版本 19 | 生态与文档最厚，长列表/虚拟滚动/图表等成熟件齐全；配 React Compiler 后自动 memo 能力追平编译型框架 |
| 编译器 | **React Compiler**（`babel-plugin-react-compiler`） | 1.x | 自动记忆化，免去手写 `useMemo`/`memo` 的纪律负担（§5） |
| 语言 | TypeScript | 见 §8 | 绑定层与事件载荷需要类型约束 |
| 构建 | Vite | 见 §8 | 迭代速度是框架三项判据之一 |
| 样式 | Tailwind CSS | v4 | 与 [09 §4](09-UI.md) 的设计 token 共用同一生成物（[09 §4.2](09-UI.md)） |
| 图标 | **lucide** | 见 §8 | 内联 SVG、`currentColor` 描边，符合 [09 §4.7](09-UI.md) 对图标的硬要求 |
| 虚拟列表 | **`@tanstack/react-virtual`** | 3.x | headless、支持**固定行高**（与 [07 `P-105`](07-EXTENSION.md) 的固定行高策略一致）；不绑定具体 DOM 结构 |
| 后端通信 | Wails 绑定 + 事件 | — | [04 §3/§4](04-INTERFACES.md) |

> **为什么不再做框架实测**：原 [13 V7](13-ROADMAP.md) 的"用打包体积 / 1000 条滚动帧率 / 迭代速度三项数据决定 Svelte 5 vs React 19"**已由用户决策关闭**——直接采用 React 19。三项判据中"1000 条列表滚动帧率"的要求本身仍然有效，它现在由 [11 `PF-A1`/`PF-A2`](11-ACCEPTANCE.md) 与 §4.4 承接，**不是**选型依据了。

**版本写法规则**：本文只锁**主版本**（避免版本号抄成两份、必然漂移——设计原则 3）。精确版本与校验和以 `package.json` + `package-lock.json` 为准（[12 §8.2](12-CONVENTIONS.md)）；实测通过的版本记录在 §8。

## 3. 工程结构

```text
frontend/
├── src/
│   ├── main.tsx              入口：挂载 + 主题首帧前注入
│   ├── app/                  应用外壳：路由/页面切换、全局布局
│   ├── pages/                五个页面（下载任务 / 视频号 / IDM / 设置 / 诊断）
│   ├── components/           可复用组件（列表、卡片、按钮、开关…）
│   ├── bindings/             Wails 绑定与事件的**唯一**封装层（§3.1）
│   ├── stores/               前端状态（按领域切分，禁止全局单一大 store）
│   ├── theme/                主题 token：由设计系统生成 CSS 自定义属性
│   └── lib/                  纯函数工具（无 DOM、无副作用）
├── index.html
├── vite.config.ts
├── tailwind.config.*
└── package.json
```

| # | 约束 |
| --- | --- |
| S1 | **`bindings/` 是唯一调用 Wails 的地方。** 组件与 store **不得**直接 `import` Wails 运行时——否则绑定层一变，全仓都要改 |
| S2 | 页面组件不直接调 `bindings/`，经 `stores/`。理由：状态归属一处，便于 §4 的订阅粒度控制 |
| S3 | `lib/` 必须是纯函数（无 DOM、无网络、无 storage），便于单测 |
| S4 | **禁止** `utils` / `common` / `helpers` 这类无边界目录（[12 §1.2](12-CONVENTIONS.md)） |

### 3.1 绑定层职责

| 职责 | 说明 |
| --- | --- |
| 方法调用 | 每个后端方法一个类型化包装；把 [04 §3.1](04-INTERFACES.md) 的 `Result<T>` 判别联合转成"数据或可读错误"，**不得**把 `ok:false` 静默当成功 |
| 事件订阅 | 每个事件一个订阅函数，**返回取消函数**（组件卸载必须调用，见 §4.1 `P-109`） |
| 乱序防护 | [04 §4.3](04-INTERFACES.md) 的本地请求序号，**只在绑定层实现一次** |
| 启动/重连对齐 | [04 §4.4](04-INTERFACES.md) 的 `PlansList()` 对齐，只在绑定层提供入口 |

**必须遵守 [04 §3.1](04-INTERFACES.md) 的四条绑定规则**（本文不重复定义，只说明落点）：

| 规则 | 在绑定层的落点 |
| --- | --- |
| B1 方法不得阻塞渲染 > 16 ms | 耗时调用异步化，结果经事件回推；绑定层不得同步等待 |
| B2 不得返回秘密字段 | 绑定层不做字段裁剪（Go 侧已保证），但**禁止**把原始响应整体透传给 UI |
| B3 列表方法必须有分页或硬上限 | 绑定层必须显式传 `offset`/`limit`，**禁止**无参调用列表方法 |
| B4 不得直接访问文件系统/进程/注册表 | 绑定层只暴露 [04 §3.2](04-INTERFACES.md) 的方法清单，不额外包一层"通用执行"入口 |

> 绑定层**不做**业务判断：它只搬数据。完成与否、能不能删，判断在 Go 侧（[02 `B-313`](02-BEHAVIOR.md)：界面只投影真实状态）。

## 4. 渲染约束（**本节是本文存在的核心理由**）

React 的默认行为是"父组件重渲染 → 整棵子树重渲染"。下面每条都是**必须主动做到**的，框架不会替你满足。

### 4.1 契约映射：扩展侧 `P-101`~`P-110` → 桌面端

扩展侧是手写 DOM，桌面端是 React，**同一意图的不同检查方式**：

| 扩展契约（[07](07-EXTENSION.md)） | 桌面端的等价约束 | 检查方式 |
| --- | --- | --- |
| `P-101` 集合不变不重绘 | 状态变化**只重渲染那一行**；行的 props 必须可比较（§4.2） | 渲染计数；React DevTools Profiler |
| `P-102` 禁止整体重建容器 | **禁止** `innerHTML`、`dangerouslySetInnerHTML`、手工 `createElement`/`appendChild` | 源码扫描（§4.3） |
| `P-103` 节点复用 | 列表项 `key` 必须用**稳定业务 ID**（计划 id），**禁止**数组下标 | 源码审查 + 重排测试 |
| `P-104` 事件委托 | 事件处理器定义在**列表项组件内部**或经 `useCallback` 稳定；禁止每次渲染新建匿名函数传进列表项 | Profiler：`props` 是否每次变化 |
| `P-105` 虚拟滚动 | 行数 > **50** 时启用 `useVirtualizer`；**固定行高**（`estimateSize` 常量），**禁止**测量式（§4.5） | 单测断言 `estimateSize` 为常量 + DOM 节点数上界 |
| `P-106` 帧预算 | 同一帧内的多次更新合并；高频事件（进度）走节流，见 §4.6 | [11 `PF-A2`](11-ACCEPTANCE.md) |
| `P-107` 缩略图用 URL | 缩略图用图片 URL + 懒加载，**禁止** base64 常驻；可视区外不赋 `src` | 内存快照 + 网络面板 |
| `P-108` 轮询受限 | 桌面端**不轮询**（[09 `PF-1`](09-UI.md)）；只在启动/重连对齐时拉一次 | 事件计数 |
| `P-109` 关闭即停 | 组件卸载必须取消订阅与定时器（绑定层返回的取消函数必须调用） | 泄漏测试 |
| `P-110` 上传不阻塞渲染 | 上传进度**不得**进入渲染帧预算；只按节流更新该行文本 | 与 `P-110` 同判据 |

> **注意**：扩展侧的 `P-101`~`P-110` 编号**不复制到本文**。本文只做映射，契约本身仍在 [07](07-EXTENSION.md) 定义（设计原则 3）。桌面端的验收编号是 [11 §2.8](11-ACCEPTANCE.md) 的 `T-UI-*` 与 §3 的 `PF-A1`/`PF-A2`。

### 4.2 列表渲染纪律

| # | 约束 |
| --- | --- |
| R1 | 列表项是**独立组件**，不能把整行 JSX 内联在列表组件的 `map()` 里——否则无法做行级记忆化 |
| R2 | `key` = 业务稳定 ID。**禁止**下标、`Math.random()`、`Date.now()` |
| R3 | 传给列表项的 props 必须是**原始值或稳定引用**。对象/函数要么来自 store 的稳定选择器，要么用 `useCallback`/`useMemo` 固定 |
| R4 | 列表容器组件**不得**订阅整张表的细粒度字段。订阅粒度到"行"，本行状态变化不得让兄弟行重渲染 |
| R5 | 派生数据（统计、过滤结果）不得在渲染中做重计算——放 store 的选择器（由编译器/`useMemo` 记忆化） |

### 4.3 硬禁止（出现一次即视为违反）

| 禁止 | 原因 |
| --- | --- |
| `dangerouslySetInnerHTML` | 等价于扩展侧 `P-102` 的整体重建，且是 XSS 面 |
| `innerHTML` / `outerHTML` 赋值 | 越过 React 的 DOM 所有权 |
| `document.createElement` / `appendChild` 操作应用区域 | 同上 |
| 用**下标**作 `key` | 重排即错位，等价于重建 |
| 在渲染期间发起 `bindings/` 调用或订阅事件 | 每次渲染都会执行，且违反 [09 `PF-1`](09-UI.md) |
| 组件内 `setInterval` 做状态同步 | 桌面端不轮询（[09 `PF-1`](09-UI.md)、[01 §4.1](01-ARCHITECTURE.md)） |

> **例外说明**：`ref` + 命令式 DOM 只允许用于**第三方 headless 库**要求的场景（如虚拟滚动的滚动容器测量），且必须集中在 `components/` 内的封装组件里，不得散落到页面。

### 4.4 列表的量化判据（与验收对齐，不重复定义）

| 判据 | 阈值出处 |
| --- | --- |
| 单条状态更新的 DOM 变更节点数 ≤ 20；500 ms 窗口内总数 ≤ 25；容器未被整体重建；主列表查询 ≤ 2 次 | [11 `PF-A2`](11-ACCEPTANCE.md) |
| 1000 条 vs 100 条的 p95 单条更新耗时之比 ≤ 2.0；列表容器 DOM 节点数 ≤ 60 | [11 `T-UI-06`](11-ACCEPTANCE.md) |
| 滚动 p95 帧率 ≥ `max(50 FPS, 基线 × 1.5)`；p99 帧时间 ≤ 33 ms；长任务(>50 ms) ≤ 2 | [11 `PF-A1`](11-ACCEPTANCE.md) |

**这三行是本文与验收的接口**：本文规定"怎么写"，[11](11-ACCEPTANCE.md) 规定"怎么判"。**不要**在本文重复阈值数字。

### 4.5 虚拟列表（`@tanstack/react-virtual`）

| 项 | 规定 |
| --- | --- |
| 启用阈值 | 行数 **> 50**（与 [07 `P-105`](07-EXTENSION.md) 一致） |
| 行高 | **固定**。`estimateSize` 必须是常量函数，**禁止** `measureElement` 测量式 |
| 为什么禁止测量式 | 只有固定行高才算得出稳定起始索引——测量式会产生滚动抖动，且破坏"滚动位置保持"（[02 `B-206`](02-BEHAVIOR.md) 的同类要求）。该决定在扩展侧已做出（[07 §10 `E6`](07-EXTENSION.md) 已因此关闭），桌面端**必须一致** |
| 缓冲 | `overscan` 用固定行数，禁止无限缓冲 |
| 滚动位置恢复 | 列表重排/切页返回后必须恢复原位置——这是 `B-206` 的同类体验要求，实现时用 `scrollToIndex` |
| DOM 节点上界 | 容器 + 可见行 + 缓冲行；判据见 [11 `T-UI-06`](11-ACCEPTANCE.md) ④ |

### 4.6 高频更新（下载进度）

| 项 | 规定 |
| --- | --- |
| 来源 | [04 §4.2](04-INTERFACES.md)：每 **200 ms** 推送一次**完整** `PlanView`；终态**立即**推送，不受节流限制 |
| 前端处理 | **直接覆盖**该条记录（不做增量合并计算） |
| 订阅粒度 | 只订阅该 `id` 的记录；**不得**因一条进度让整个列表重渲染 |
| 终态 | 必须立即渲染，**不得**被前端自己的节流吞掉（[09 `PF-8`](09-UI.md)） |
| 乱序 | 用 [04 §4.3](04-INTERFACES.md) 的本地请求序号，**在绑定层实现一次** |

### 4.7 页面切换与主题

| 项 | 规定 |
| --- | --- |
| 页面切换 | **不重建整棵应用树**（[09 `PF-6`](09-UI.md)）。页面间共享的外壳（侧栏、标题栏、顶部状态）必须是同一组件实例 |
| 主题首帧 | 主题必须在**首帧前**确定：由绑定层注入初始值或在 `main.tsx` 内联读取持久值（[09 §4.3](09-UI.md)、`B-803`）——**不得**先渲染默认色再切换 |
| 主题切换 | 通过切换 CSS 自定义属性实现（Tailwind v4 的 `@theme`），**不触发组件树重建**；`B-805` 要求无旧主题残留 |
| token 单一来源 | CSS 变量与 Tailwind 主题**共用同一个生成物**（[09 §4.2](09-UI.md)），禁止两处各写一套值 |

## 5. React Compiler

### 5.1 安装与配置（Vite）

```text
npm install -D babel-plugin-react-compiler@latest
npm install -D @rolldown/plugin-babel
```

```js
// vite.config.js
import { defineConfig } from 'vite';
import react, { reactCompilerPreset } from '@vitejs/plugin-react';
import babel from '@rolldown/plugin-babel';

export default defineConfig({
  plugins: [
    react(),
    babel({ presets: [reactCompilerPreset()] }),
  ],
});
```

| # | 约束 |
| --- | --- |
| C1 | 编译器**必须最先运行**：它需要原始源码信息，必须早于其它转换 |
| C2 | 使用 `@vitejs/plugin-react` **6.0.0 及以上**时用 `reactCompilerPreset`；6.0.0 起移除了内联 `babel` 选项（旧写法见官方文档） |
| C3 | ESLint 必须配 `eslint-plugin-react-hooks` 的 **`recommended-latest`** —— 编译器规则会指出哪些组件**无法被优化** |
| C4 | `use no memo` 指令**默认禁止**。只在定位到具体问题时临时使用，且必须在同一提交内记录原因；修好后立即删除 |

### 5.2 如何验证编译器真的在工作（**验收要求**）

| 手段 | 判据 |
| --- | --- |
| React DevTools | 被优化的组件显示 **"Memo ✨"** 徽章 |
| 构建产物 | 出现 `react/compiler-runtime` 的 `_c(n)` 调用 |
| ESLint | `recommended-latest` 无编译阻断类报错 |

> **这是可自动化的**：构建产物里断言 `compiler-runtime` 存在，即可在 CI 上机械确认编译器没被静默关掉。**"上了编译器"不能只写在文档里。**

### 5.3 编译器不豁免的纪律（**关键**）

React Compiler 做的是**记忆化**，它**不能**保证"单条更新只改一行"。以下必须人工保证：

| # | 仍然必须做到 | 原因 |
| --- | --- | --- |
| M1 | 列表项是独立组件 + 稳定 `key`（§4.2 R1/R2） | 记忆化是"按组件"的：整行内联在 `map()` 里就没有可记忆的边界 |
| M2 | props 可比较（§4.2 R3） | 每次渲染新建的对象/函数会让记忆化**每次失效** |
| M3 | 订阅粒度到行（§4.2 R4） | 若容器订阅了每行的状态，容器必然重渲染 |
| M4 | **`@tanstack/react-virtual` 的 opts 对象要稳定** | 该库内部依赖 opts 引用；渲染中新建对象会导致重复测量/重排。用 `useMemo` 或模块级常量 |
| M5 | 副作用与订阅在 `useEffect` 里、卸载时清理（§4.1 `P-109`） | 编译器不管生命周期 |

> **一句话**：**编译器负责"少算"，不负责"少渲染"。** 本文 §4 的约束是渲染粒度问题，编译器解决不了。

### 5.4 不上编译器的退路（仅当某组件被 ESLint 判定无法优化）

| 退路 | 规定 |
| --- | --- |
| 手写记忆化 | `React.memo` 包列表项 + `useCallback` 稳定回调 + `useMemo` 稳定对象/派生值 |
| 纪律要求 | 与 §5.3 的 M1~M5 **完全相同**，一个都不能省 |
| 禁止 | 用 `React.memo` 包裹后仍传内联对象/函数——那是**假优化**，每次都会失效 |

## 6. 复用优先（"有能复用的就不要重复造轮子"）

### 6.1 优先用成熟件

| 能力 | 用什么 | 不要自己写 |
| --- | --- | --- |
| 虚拟滚动 | `@tanstack/react-virtual` | 手写 IntersectionObserver 窗口计算 |
| 图标 | lucide | 手绘 SVG 图标集 |
| 样式体系 | Tailwind CSS + 设计 token | 手写 CSS 框架 / CSS-in-JS 运行时 |
| 构建与 HMR | Vite | 自建打包脚本 |
| 组件原语（下拉、开关、提示） | 原生元素 + Tailwind，必要时 headless 库（如 Radix 系） | 手写可访问性完整实现 |
| 主题持久化与首帧注入 | 绑定层 + CSS 变量 | 渲染后再改 class 的补丁式换肤 |

**规则 F-1**：新增前端依赖前，先按 [12 §8.2](12-CONVENTIONS.md) 回答"用途 + 许可证"，并在提交信息里写明理由。**禁止**引入与既有能力重复的大型框架（[12 §8.2](12-CONVENTIONS.md) 的禁令）。

### 6.2 必须自研（不存在可用的成熟件）

| 自研项 | 为什么 |
| --- | --- |
| 列表渲染纪律（§4） | 这是本项目最突出的体验问题（旧版每秒全量重建 DOM），**没有库能替你保证** |
| 绑定层（§3.1） | 与 Go 侧接口一一对应，含乱序防护 |
| 与 `P-101`~`P-110` 的映射实现 | 桌面端与扩展侧语义对齐是项目特有约束 |
| 下载进度的高频更新处理（§4.6） | 与 [04 §4.2](04-INTERFACES.md) 的 200 ms 契约绑定 |

### 6.3 与扩展侧的关系

| 项 | 规定 |
| --- | --- |
| 代码 | **不共享**。扩展是原生 JS 且无构建（[12 §1.1](12-CONVENTIONS.md)） |
| 设计 token | **共享**：`P-105`/`AD-9` 要求弹窗与桌面端共用同一套 token（[07 `AD-9`](07-EXTENSION.md)） |
| 契约语义 | **对齐**：§4.1 的映射表是唯一对应关系，改一侧必须同步另一侧 |
