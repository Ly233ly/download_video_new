# 10 · 安装与发行

本文定义安装器职责、升级回滚、卸载、自动更新与载荷边界。

---

## 1. 安装

```text
1. 检查代理残留 → 存在则先恢复（[01 §5.1](01-ARCHITECTURE.md)）
2. 通知旧实例退出，**等待相关进程全部结束**（超时则中止安装并提示）
3. 解包载荷到目标目录
4. 写入注册表：程序状态与卸载入口（**不写扩展 Origin**——扩展 ID 由 manifest 固定 `key` 决定，内置在程序常量中）
5. 处理 IDM 集成（见 §6）
6. 创建开始菜单快捷方式
7. 启动桌面端
8. 打开扩展目录供用户手动加载
```

| 项 | 规定 |
| --- | --- |
| 形态 | 单文件可执行，载荷整体嵌入 |
| 技术 | Go 自研 |
| 权限 | 只操作能**验证归属**的对象（B-911） |
| 测试模式 | 必须支持 `--test-install` / `--test-uninstall` 供自动化调用 |

**浏览器扩展边界**：安装器只能**打开目录**并提示，**禁止**绕过浏览器安全边界自动安装。用户必须亲自完成"加载已解压的扩展程序"。

---

## 2. 升级

### 2.1 流程

```text
1. 检查代理残留 → 恢复
2. 通知旧程序：恢复代理、停止捕获，**等待其进程、WebView 子进程与外部工具全部结束**（超时则中止并提示）
3. 旧程序目录改名为 `*.bak-<时间戳>`
4. 解包新版本
5. 启动新版本
6. 用户确认运行正常后可手动删除 `*.bak-*`
```

### 2.2 失败恢复

**第一版不做自动健康检查与自动回滚。**

| 情况 | 用户可做 |
| --- | --- |
| 新版本启动失败 | 手动把 `*.bak-*` 改回原目录名 |
| 安装中途失败 | 备份目录未被破坏，可手动恢复 |

> **关于数据库**：新版本结构版本为 `1` 且**不做历史迁移**（[03](03-DATA.md)）。首次安装时新建库；若目标目录已存在旧版本数据库，安装器**不读取也不删除**它。因此不存在"回滚后旧程序读不了已迁移的库"这个问题。

## 3. 卸载

### 3.1 删除范围

| 删除 | 说明 |
| --- | --- |
| 程序文件 | 只删能验证归属的 |
| 快捷方式 | 只删本程序创建的 |
| 注册表项 | 状态与卸载入口 |
| 视频号证书 | 按**指纹精确**删除 |
| 代理设置 | 只恢复本程序拥有的 |

### 3.2 明确不删除

| 保留 | 理由 |
| --- | --- |
| 用户下载的视频 | 用户资产（B-401） |
| IDM 原文件 | 用户资产 |
| Eagle 内容 | 第三方资产 |
| 其他软件的代理设置 | 他人资产（B-719） |
| 用户数据库中的历史记录与规则 | 默认保留 |
| `media-tools/` 与 `licenses/` | 若用户选择"保留数据" |

### 3.3 用户需自行完成

浏览器中手动加载的扩展需用户在扩展管理页自行移除。安装器**不得**代劳。

## 4. 更新

### 4.1 定位

**第一版不做后台静默自动更新，也不做原子回滚。**

```text
检查新版本
  → 有新版本：提示用户
  → 用户点击「下载更新」
  → 下载安装器
  → 用户确认后运行，覆盖安装
```

### 4.2 直接下载安装器，不解 ZIP

Release 同时发布两个资产：

| 资产 | 使用者 | 形式 |
| --- | --- | --- |
| `LiudiDownloader-Setup.exe` | **应用内更新** | 单文件安装器 |
| `LiudiDownloader.zip` | 用户手动下载 | 完整包（含说明、许可证） |

应用内更新因此是：

```text
GitHub Release
  → 下载 Setup.exe
  → 校验来源 / 大小 / SHA-256
  → 用户确认后运行
```

**完全不需要**：ZIP 解压、ZipSlip 防护、条目数上限、压缩比上限、大小写冲突检测、路径类型冲突检测、解压后定位安装器。

### 4.3 保留的安全校验

| 项 | 规定 |
| --- | --- |
| 来源 | 固定仓库的 GitHub **正式** Release（B-904） |
| 资产唯一性 | Windows 资产必须唯一，且名称匹配固定规则 |
| 传输 | HTTPS |
| 跳转 | 元数据禁止跳转；资产只允许一次跳转到官方资产域名 |
| 摘要 | 校验 GitHub 官方 `sha256` |
| 大小 | 声明大小为**正整数**且 ≤ 250 MB；实际字节数必须与声明一致 |
| 失败 | 清理临时文件 |

> **升级失败后怎么办**：见 §2.2。第一版不用自动健康检查与自动回滚，靠覆盖前的 `*.bak-*` 备份手动恢复（成本低得多），等产品稳定后再考虑自动化。本文不重复那张恢复表。

## 5. 载荷边界

### 5.1 用户 ZIP 内容

**只能包含**（B-901）：

1. 单文件安装器
2. 使用说明
3. 许可证
4. 二进制清单
5. 源码获取说明

### 5.2 必须包含的运行时资产

| 资产 | 来源 |
| --- | --- |
| FFmpeg / FFprobe | `media-tools/` |
| yt-dlp / Deno | `media-tools/` |
| 扩展运行文件（JS/HTML/CSS/图标） | `extension/` |
| 许可证文本 | `licenses/` |

### 5.3 禁止暴露

用户可见发行目录**不得**包含（B-902）：

- Go / TypeScript 源码
- 构建配置
- source map
- 临时构建目录
- 开发机数据、配对令牌、站点规则、任务记录、用户路径

> **注意**：浏览器扩展的 JS 是**运行必需品**，不属于"源码暴露"范围。载荷扫描规则必须区分"扩展运行文件"与"开发源码"，避免误删。

### 5.4 合规

**全部上游来源、许可证义务与三类边界统一登记在 [15 · 上游来源与第三方合规](15-UPSTREAM.md)**，本节不重复。

发行前必须确认的三件事：

| # | 要求 |
| --- | --- |
| 1 | 组合发行许可为 **GPL-3.0**（因复用 cat-catch，见 [15 §2.2](15-UPSTREAM.md) 的传染性说明） |
| 2 | **对应源码必须与二进制发行同时可得** |
| 3 | 固定版本 + SHA-256 与许可证通知齐备（[15 §4](15-UPSTREAM.md)、[15 §5](15-UPSTREAM.md)） |

**ISAAC-64** 依据公共领域算法说明独立实现，以公共领域测试向量验证（[15 §3.3](15-UPSTREAM.md)）。

## 6. IDM 保护

| 情况 | 允许的动作 |
| --- | --- |
| IDM 病毒检查设置为**空** | 可以配置本程序 hook |
| IDM 已指向本程序的**旧安装位置** | 可以更新为当前路径 |
| IDM 已指向**其他杀毒软件** | **不得覆盖**（B-606） |
| IDM 指向**无法确认归属**的程序 | **不得覆盖** |

**卸载时**：只有当前设置仍指向本程序，才恢复安装前的值。

---

## 7. 证书

| 阶段 | 安装器职责 |
| --- | --- |
| 安装 | **不主动安装**证书；由用户在首次捕获时确认（B-702） |
| 升级 | 指纹匹配则**保留**，不重复要求确认 |
| 卸载 | 按**指纹精确**删除本程序证书 |

**禁止**：修改机器级根证书存储；删除非本程序证书。
