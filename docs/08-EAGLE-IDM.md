# 08 · Eagle 与 IDM

本文定义 Eagle 调用契约、导入与补导、内容去重、文件所有权，以及 IDM 处理流水线。

---

## 1. Eagle 定位

| 项 | 规定 |
| --- | --- |
| 性质 | **可选**归档能力，不是下载引擎依赖（B-502） |
| 访问 | **只**调用官方本地 Web API；禁止直接修改 `.library`（B-501） |
| 默认地址 | `http://127.0.0.1:41595` |
| 网络 | 直连，**不经过**任何代理（B-314） |
| 失败影响 | 不得阻止下载、打开文件、停止、重试或清理记录 |

---

## 2. Eagle 客户端契约

### 2.1 端点与回退

每个操作支持 v2 端点，**仅在收到 HTTP 404 或 405 时**回退到旧端点：

| 操作 | 主端点 | 回退端点 |
| --- | --- | --- |
| 应用信息 | `GET /api/v2/app/info` | `GET /api/application/info` |
| 按路径添加 | `POST /api/v2/item/add` | `POST /api/item/addFromPath` |
| 更新来源 | `POST /api/v2/item/update` | `POST /api/item/update` |

### 2.2 请求约定

| 项 | 规定 |
| --- | --- |
| 超时 | 默认 **4 秒** |
| 请求头 | `Accept: application/json`；有请求体时 `Content-Type: application/json; charset=utf-8` |
| 编码 | UTF-8（不转义中文） |
| 成功判定 | 响应的 `status` 必须是 `"success"` 或 `true` |

### 2.3 错误分类

| 类别 | 触发 | 处理 |
| --- | --- | --- |
| 不可用 | 连接失败、超时、网络错误 | 判定 Eagle 不可用，进入等待或降级 |
| 端点不存在 | HTTP **404 / 405** | 触发端点回退 |
| 导入失败 | 其他 HTTP 状态、非 JSON、`status` 非成功 | 可重试 |

**分类优先级**：传输层错误（超时/连接失败）优先判定为"不可用"；只有收到 HTTP 响应后才按状态码分类。

### 2.4 添加载荷

| 字段 | 值 |
| --- | --- |
| `path` | 文件绝对路径 |
| `name` | 文件名去扩展名 |
| `tags` | 空数组 |
| `annotation` | 空字符串 |
| `website` | 仅在有**可靠来源**时提供（B-507） |

## 3. 可用性与降级

### 3.1 能力发布

| 要求 | 契约 |
| --- | --- |
| 健康接口发布 `eagleAvailable` | B-503 |
| 不可用时关闭导入与删除意图 | B-504 |
| 旧扩展请求导入也要安全降级 | B-504 |
| 顶部状态显示「Eagle 未连接 · 下载可用」 | B-809 |

### 3.2 内存熔断

一个不可达的本地 Eagle 端点会让每个排队文件各消耗一次完整超时。必须实现短时熔断：

| 项 | 规定 |
| --- | --- |
| 触发 | 一次"不可用"判定 |
| 窗口 | **5 秒** |
| 效果 | 窗口内任务直接进入等待，不再尝试连接 |
| 恢复 | 窗口过期后允许重新探测 |
| 作用域 | 仅内存，不持久化 |

## 4. 导入与补导

### 4.1 导入流程

```text
导入请求（IDM 任务 或 已完成计划补导）
  → 校验文件存在且稳定（见 §8.2）
  → 计算 SHA-256 指纹
  → 查指纹归属
      ├─ 属于本任务且有 eagle_item_id → 直接标记 imported（幂等）
      ├─ 属于其他任务 → skipped（error_code = duplicate），保留本机文件
      └─ 无归属 → 继续
  → POST item/add
  → 成功：记录指纹 + 标记 imported + 记录 eagle_item_id
  → 失败：按 §2.3 分类重试或等待
```

### 4.2 补导

**`plan` 完成后状态恒为 `completed`，补导不改变它。** 补导的产物是一条 `jobs` 记录。

| 场景 | 语义 |
| --- | --- |
| 首次补导 | 创建一条 `jobs` 记录并设 `plan_id = plan.id`（`status = queued`），`plan.status` 保持 `completed` |
| 正在导入 | 并发点击**复用**同一条未终结的 `jobs` 记录（B-505） |
| 已导入 | 若已有 `imported` 的 `jobs` 记录，提示已导入，不重复创建 |
| 状态已变化 | 报 `plan_state_changed`，前端刷新后重试 |

**原子性**：使用 `BEGIN IMMEDIATE` 检查并创建或复用唯一 `jobs` 记录，不得产生孤立任务。

**可补导的 plan 状态**：任何 `completed` 的 plan 都可以补导，与该 plan 是否曾导入无关——是否已导入由 `jobs` 决定。

> 这一条同时修正了两处历史问题：早期文档只允许 `ready_to_import` 补导（导致「仅下载完成」反而没有入口）；后来又把 `completed_local` 当终态却规定它转成 `ready_to_import`（终态变非终态）。现在下载与导入各有独立状态机，互不改写。
### 4.3 导入结果不明

若 Eagle 调用成功但响应丢失或本地提交失败，**本地无法确认导入是否已发生**。采用如下取舍：

| 措施 | 说明 |
| --- | --- |
| 状态 | `jobs.status` 保持 `queued`，`attempt_count` 递增 |
| 去重 | 重试前先算指纹并查 Eagle 侧是否已存在（若 API 支持），否则依赖本地指纹表 |
| 重试 | 允许重试，因此**偶尔可能产生重复项**——这是已接受的取舍 |
| 不重下 | 媒体已在本机，**不得**因导入结果不明而重新下载 |
| 不删源 | 未确认成功**不得**作为删除本机副本的依据（B-402 的校验必须通过） |
| 人工 | Eagle 内的重复项由用户自行合并，代价远低于对账状态机 |

> 简化取舍：不做复杂的 reconciliation 状态机。Eagle 的重复项用户可在 Eagle 内合并，代价远低于复杂状态机。

## 5. 内容指纹

| 项 | 规定 |
| --- | --- |
| 算法 | SHA-256（整文件流式） |
| 存储 | `fingerprints` 表（[03 §2.3](03-DATA.md)） |
| 用途 | 跨任务去重 |
| 幂等 | 同任务重复处理时，已有指纹与 `eagle_item_id` 直接判定成功 |
| 大文件 | 必须流式计算，不整文件入内存 |
| 文件变化 | 若文件在哈希后被修改（`mtime`/大小变化），必须重新哈希 |

**范围**：指纹不区分 Eagle 库。用户切换库后指纹仍有效——这是已知取舍，代价是"切库后可能跳过本应重新导入的内容"。

## 6. 三类文件与所有权

| 类别 | 定义 | 允许的操作 |
| --- | --- | --- |
| **用户 / IDM 原文件** | IDM 下载的文件、用户自己的文件、目录外文件 | **永不**移动、删除或修改（B-401） |
| **程序临时文件** | 程序创建的临时分片、中间产物、解密中间文件 | 只有存在明确任务归属时才可清理（B-404） |
| **程序创建的最终副本** | 程序写入「已完成」目录的交付文件 | 只有归属校验通过才可删除（B-402） |

**默认姿态：保留。** 归属不明确、导入失败、文件锁定或目录外路径都必须保留（B-403）。

## 7. 保留期删除

`delete_after_import` 生效后的删除必须通过校验。

### 7.1 校验条件

```text
1. final_path 解析后是一个文件（非目录、非符号链接）
2. final_path 解析后 == job.file_path 解析结果
3. final_path 解析后位于「已完成」目录之内
4. 该路径是程序创建时记录的（存在对应计划记录）
```

任一不满足 → 拒绝删除，记录 `not_owned`。

### 7.2 路径解析失败

任一路径解析抛错 → 拒绝删除并记录，不重试。

### 7.3 删除重试

| 项 | 规定 |
| --- | --- |
| 重试 | 4 次，间隔 200 ms |
| 全失败 | 记录 `delete_failed`，消息含最后一次异常类型 |
| 消息长度 | 截断至 1000 字符 |

### 7.4 与其他队列的隔离

保留期清理与 IDM 导入批次**相互独立**。

**关键约束**（B-602）：没有 Eagle 的机器会不断产生 `waiting` 行填满导入批次，这**不得**让已到期且通过归属校验的清理饿死。处理循环每轮都必须无条件执行清理。

## 8. IDM 流水线

### 8.1 两段式结构

```text
【快速路径】IdmEagleHook.exe
   写 inbox 文件 → 发命名事件 → 退出
        ↓
【后台路径】主程序
   消费 inbox → 稳定性检测 → 指纹 → 去重 → 导入
   同时独立执行保留期清理
```

### 8.2 文件稳定性检测

| 检查 | 处置 |
| --- | --- |
| 文件不存在 | 重试，错误码 `file_missing` |
| `size <= 0` | 重试，延迟 **3 秒**，上限 **20 次** |
| `now - mtime < 2 秒` | 重试，延迟 `max(0.5, min(3.0, 2.0 - age + 0.25))`，上限 **20 次** |

**参数沿用旧项目实测值**：`minimum_file_age = 2.0` 秒。

### 8.3 非视频判定

| 条件 | 处置 |
| --- | --- |
| 扩展名不在视频集合**且**无关联下载计划 | 标记 `skipped`（error_code = `non_video`） |
| 扩展名不是视频**但**有程序创建的下载计划 | 允许继续（如程序生成的音频，B-603） |

### 8.4 来源判定

仅当任务既无来源事件也无 `source_url` 时尝试附加。

| 参数 | 值 |
| --- | --- |
| 来源宽限期 | **4 秒**（沿用旧项目实测值） |
| 宽限期内 | 设置 `next_attempt_at`，错误码 `source_grace` |
| 宽限期后 | **无来源也导入**，不写 `website` |

**禁止猜测网址**（B-507）。

### 8.5 重试

| 项 | 规定 |
| --- | --- |
| 通用退避 | `min(15 × 2^(attempt-1), 900)` 秒 |
| 默认上限 | **12** 次 |
| 达上限 | 状态 `failed`（错误码 `retry_exhausted`） |

### 8.6 等待 Eagle

| 项 | 规定 |
| --- | --- |
| 间隔 | **30 秒** |
| 上限 | **120** 次（约 1 小时） |
| 未达上限 | 状态 `waiting` |
| 达上限 | 状态 `failed`，错误码 `eagle_unavailable` |

**契约**：等待 Eagle 的任务不得占用或阻塞媒体下载队列（B-602）。

## 9. 错误码

| 错误码 | 含义 | 可重试 |
| --- | --- | --- |
| `non_video` | 非视频格式（jobs 标记 skipped） | 否 |
| `source_grace` | 正在等待来源宽限期 | 是 |
| `file_missing` | 文件暂时不存在 | 是 |
| `file_not_stable` | 文件未稳定或为空 | 是 |
| `file_read_error` | 无法读取文件 | 是 |
| `duplicate` | 内容已导入 | 否 |
| `eagle_unavailable` | Eagle 不可达 | 是（上限内） |
| `eagle_import_error` | Eagle 拒绝导入 | 是 |
| `not_owned` | 归属校验失败，拒绝删除 | 否 |
| `delete_failed` | 归属通过但物理删除失败 | 是 |
| `plan_not_importable` | 计划状态不允许导入 | 否 |
| `plan_state_changed` | 状态已变化 | 否 |
| `retry_exhausted` | 重试耗尽 | 否 |
